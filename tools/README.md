# tools · 教程配套工具

这里有四个工具，分别负责：**生成阅读版 HTML**、**生成练习站 HTML**、**仓库自检**、**练习站测试**。

## 0. 一次性准备

```bash
cd tools
npm install
```

依赖只有两个：`marked`（Markdown → HTML）、`jsdom`（练习站 DOM 测试）。

---

## 1. 阅读版 HTML（`build-html.mjs`）

把 `docs/` 下所有 Markdown 章节合成**一个自包含的单文件 HTML**。

```bash
npm run build:html     # 输出覆盖根目录的 Python从零到一-阅读版.html
```

**只有当你修改了 `docs/` 或 `README.md` / 速通版之后，才需要重新生成。**

生成的 HTML 有什么：

- 左侧**侧边栏导航**：按章节 + 二级标题（h2）自动生成
- 滚动时**自动展开当前章**的二级目录
- 顶部**搜索框**：实时过滤目录，回车跳到第一个匹配的章节
- 顶部**阅读进度条** + 右下角**回到顶部按钮**
- **打印友好**：`@media print` 下自动隐藏侧边栏，每章分页
- **完全自包含**：CSS 和 JS 都内联，不依赖网络，双击就能看

脚本做了什么：

1. 按顺序收集 `README.md` → `速通版-…md` → `docs/00…11`
2. 把章节之间形如 `[第 03 章](03-函数与闭包.md)` 的**内部链接重写成页内锚点**，
   找不到目标的链接会退化成纯文本，避免死链
3. 用 `marked`（GFM 模式）转 HTML，标题自动生成 id
4. 收集每章的 h2 生成侧边栏
5. 内联样式与脚本，输出单文件

## 2. 练习站 HTML（`extract-quiz.mjs` + `build-practice.mjs`）

把教程里的题目抽成结构化题库，再注入交互模板，产出**可答题的练习站**。

```bash
npm run build:practice
```

这条命令做了两件事：

**第一步 `extract-quiz.mjs`** —— 从 Markdown 抽取题库，输出 `site/quiz-bank.json`：

| 来源 | 抽取内容 |
|---|---|
| `docs/10-测试题与答案.md` | 第一关 20 道判断题（题干 + 对错 + 解析 + 出处章节） |
| `docs/10-测试题与答案.md` | 第二关 25 道"说出输出"（代码片段 + 真实输出 + 关键点） |
| `docs/11-面试速查表.md` | 约 50 道面试问答（问句 + 完整答案） |

抽取后会**自检**：题数是否正好 20/25、有没有缺答案/缺解析、
第一关答案是否一边倒（防止解析错位）。有问题会打印 ⚠ 并以非零退出码结束。

**第二步 `build-practice.mjs`** —— 把 `quiz-bank.json` 注入 `practice-template.html`，
产出**根目录的 `Python从零到一-练习站.html`**。

练习站功能：

- **第一关**：点"对/错"即时判分，显示正确答案 + 解析 + "回看第 XX 章"标签
- **第二关**：先自己在脑子里跑一遍，再点"查看答案"对照（输出在真实 Python 上验证过）
- **错题本**：第一关答错的题自动收集，带出处章节，可单题重做
- **面试速查**：50 道题可折叠，支持关键词实时搜索
- **进度条 + 正确率统计**，进度存在浏览器 `localStorage`，关掉再开还在
- **完全自包含**：单文件，零外部请求，双击即用，离线可答

> 改了题目正文后，重新跑 `npm run build:practice` 即可同步到练习站。

## 3. 仓库自检（`check.mjs`）

```bash
node check.mjs
```

检查七项：

1. **文档清单**：每个文件的行数与总字节
2. **编码**：UTF-8、无 BOM、**正文**无 U+FFFD 解码失败字符
   （代码块内刻意演示的乱码会被识别并豁免）
3. **内部链接**：扫描所有 `[](...)` 链接，报告死链
4. **章节齐备性**：`docs/` 下 00–11 是否都在
5. **配套代码**：列出所有示例文件行数，检查是否残留 `_` 开头的临时文件
6. **阅读版 HTML**：section 配对、表格/代码块数量、有无未渲染的反引号
7. **根目录清洁度**：检查是否有 `.tmp*`/`.log`/`.bak` 等临时文件

输出最后会给出 `全部检查通过 ✅` 或 `存在 N 个问题 ❌`，退出码可用于 CI。

## 4. 练习站 DOM 测试（`test-practice.mjs`）

```bash
npm test
```

用 `jsdom` 真实加载练习站 HTML，模拟点击验证交互：

判分正确性、错题本收集与单题重做、进度条与统计数字、标签页切换、
面试题搜索过滤（含无匹配空状态）、`localStorage` 持久化等。

---

## 已知边界

- 章节里的 `examples/xxx.py` 这类链接指向仓库内的代码文件，**在浏览器里点不动**
  （这是单文件 HTML 的固有限制），保留原样是为了让你知道该去哪个文件看。
- Markdown 里用到的 `<details>` / `<summary>`（各章的折叠答案）会被原样输出，
  现代浏览器和 GitHub 都支持；如果你的渲染环境不支持，答案会平铺展示，内容不丢。
- 练习站依赖 `localStorage` 存进度。用 `file://` 双击打开时，部分浏览器
  （如 Chrome 的严格模式）可能限制 `localStorage`——此时答题仍正常，只是进度不保存。
  想要进度持久化，用一个本地静态服务器打开即可（例如 `npx serve`）。

---

## 5. 一键全量校验

```bash
npm run build:all && node check.mjs && npm test
```

依次完成：重建练习站 → 重建阅读版 → 仓库自检 → 练习站交互测试。
