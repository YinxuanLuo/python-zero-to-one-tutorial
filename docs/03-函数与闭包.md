> 本章你需要记住的就一件事：**Python 里函数是"一等公民"——它能被赋值、被传参、被嵌套定义、被别的函数"制造"出来。剩下的一切（闭包、装饰器、lambda）都只是这个事实的推论。**

## 3.1 函数：从 JS 的 `function` 到 Python 的 `def`

你写过 JS，所以你对函数不陌生。但先抛一个结论，它可能是本章最重要的一句话：

**在 Python 里，函数是一个对象。** 你可以把它赋值给变量、塞进列表、当成参数传给别的函数、甚至用函数"制造"函数。

这一点和 JS 一样（JS 里 `function` 也是一等公民）。所以这章你真正要学的，不是"函数怎么写"，
而是"当函数是一等公民时，Python 用它玩出了哪些 JS 里不常见的花样"。

先看最朴素的定义：

```python
def greet(name):
    return f"hello, {name}"

print(greet("alice"))
```

```text
hello, alice
```

对比 JS，你立刻能感受到三个差别：

| 维度 | JavaScript | Python |
|---|---|---|
| 声明关键字 | `function` 或箭头函数 | `def` |
| 函数体边界 | `{}` | 缩进（第 00 章讲过，缩进就是语法） |
| 返回类型声明 | 无 | 无（可选类型注解，第 07 章讲） |
| 末尾分号 | 有 | 无 |

**`def` 是 statement，不是表达式。** 这意味着你不能像 JS 里那样把一个 `function` 直接塞进参数里
（那活儿交给 `lambda`，3.14 节讲）。

再看一个让 JS 老手会心一笑的例子——函数确实是对象：

```python
def greet(name):
    return f"hello, {name}"

f = greet           # 把函数赋值给变量，不带括号
print(f("bob"))     # hello, bob
print(type(greet))  # <class 'function'>
```

```text
hello, bob
<class 'function'>
```

注意 `f = greet` **没有括号**。有括号是"调用"，没括号是"把这个函数对象本身拿过来"。
这是后面理解装饰器的钥匙，先记住这个区别。

> 一句话记住它：**函数是对象，`greet` 是对象本身，`greet("bob")` 才是调用它。**

## 3.2 参数：位置参数和关键字参数

JS 里函数调用只有一种传参方式——按位置传。Python 多给你一种：**按名字传**。

```python
def introduce(name, age, city):
    return f"{name} 来自 {city}，今年 {age} 岁"

# 位置参数：按顺序一一对应
print(introduce("alice", 20, "beijing"))

# 关键字参数：明确写"谁 = 什么"，顺序无所谓
print(introduce(age=20, city="shanghai", name="bob"))

# 混合：先位置后关键字
print(introduce("carol", age=22, city="guangzhou"))
```

```text
alice 来自 beijing，今年 20 岁
bob 来自 shanghai，今年 20 岁
carol 来自 guangzhou，今年 22 岁
```

**关键字参数最大的好处是"自文档化"。** 看这两行，哪个读起来不用查函数定义？

```python
create_user("alice", 20, "beijing", True, "vip", 30)
create_user(name="alice", age=20, city="beijing", active=True, role="vip", credits=30)
```

第二行哪怕你没看过 `create_user` 的定义，也能猜个八九不离十。这就是第 00 章说的"显式优于隐式"。

### 这条规则的代价：传参顺序有硬性约束

Python 强制"**位置参数必须在关键字参数前面**"。反过来写，直接是语法错误：

```python
def introduce(name, age, city):
    return name

print(introduce(age=20, "alice", city="beijing"))
```

运行 `python x.py` 会看到：

```text
SyntaxError: positional argument follows keyword argument
```

这是**编译期**报错，不是运行期——也就是说，你这行代码根本不会开始执行，Python 读的时候就拒了。

再想一个问题：如果同一个参数被传了两次会怎样？

```python
def introduce(name, age):
    return name

print(introduce("alice", name="bob"))
```

```text
TypeError: introduce() got multiple values for argument 'name'
```

`name` 先被位置参数占了，又被关键字参数指了一次，Python 直接拒绝，不猜你要哪个。
这就是"不猜你的意图，猜错不如报错"。

如果传了函数根本不认识的参数：

```python
print(introduce("alice", 20, gender="female"))
```

```text
TypeError: introduce() got an unexpected keyword argument 'gender'
```

这三条报错（顺序、重复、未知）你以后会天天见。**它们的共同点是：Python 在参数这件事上零容忍，
任何歧义都当场报错，绝不帮你悄悄兜底。**

> 一句话记住它：**关键字参数让调用"自文档化"，代价是顺序和唯一性都有硬规则——位置在前、关键字在后、同一个参数只能传一次。**

## 3.3 默认参数，和那个臭名昭著的可变默认参数坑

默认参数你肯定熟——JS 里 `function f(a = 1) {}`。Python 写法一样：

```python
def greet(name, greeting="hello"):
    return f"{greeting}, {name}"

print(greet("alice"))                  # 不传 greeting，用默认值
print(greet("bob", greeting="hi"))     # 覆盖默认值
```

```text
hello, alice
hi, bob
```

但 Python 的默认参数里藏着一个**整个语言最著名的坑**，几乎每个 Python 面试都会考，必须单独拎出来讲透。

### 坑：默认参数是可变对象（list / dict / set）

看这段代码，你先在心里猜一下输出：

```python
def add_item(item, cart=[]):
    cart.append(item)
    return cart

print(add_item("apple"))
print(add_item("banana"))
```

你八成以为输出是：

```text
['apple']
['banana']
```

**真实输出是：**

```text
['apple']
['apple', 'banana']
```

第二次调用 `add_item("banana")`，结果里居然还留着第一次的 `"apple"`！

### 为什么？因为默认参数只在"函数定义时"求值一次

关键结论：**`cart=[]` 里的那个 `[]`，是在 `def` 这一行被执行时创建的，之后永远复用同一个列表对象。**

换句话说，`[]` 不是"每次调用都新建一个空列表"，而是"定义函数时建一个，以后每次调用都用这一个"。

这跟 JS 完全不同。JS 里 `function f(x = []) {}` 是**每次调用都新建**一个新数组。
所以从 JS 过来的人，第一反应都是"这不就正常吗"，然后踩坑。

你可以验证——看看三次调用拿到的是不是同一个列表的"身份证"：

```python
def add_item(item, cart=[]):
    cart.append(item)
    return cart

a = add_item("apple")
b = add_item("banana")
print(a is b)   # True，说明两次返回的是同一个列表对象
```

```text
True
```

`is` 判断的是"是不是同一个对象"（对比 `==` 判断的是"值相不相等"）。`a is b` 是 `True`，
证明 `a` 和 `b` 就是同一个列表，两次调用都在往同一个列表里塞东西。

### 正确做法：默认值用 `None`，函数体内再建

```python
def add_item(item, cart=None):
    if cart is None:
        cart = []        # 只有"没传"时才新建一个空列表
    cart.append(item)
    return cart

print(add_item("apple"))
print(add_item("banana"))
```

```text
['apple']
['banana']
```

现在每次不传 `cart` 时，`if cart is None` 成立，就当场新建一个 `[]`，各用各的，互不污染。

**为什么用 `None` 而不是别的？** 因为 `None` 是不可变对象，怎么复用都没关系。
社区的约定就是：**凡是要用"空列表/空字典"当默认值的，一律用 `None` 代替，进函数体再建。**

> 一句话记住它：**默认参数在函数定义时只求值一次，所以永远别用 `[]`、`{}` 这种可变对象当默认值——用 `None` 兜底，进函数体再建。**

## 3.4 `*args` 和 `**kwargs`：收下任意数量的参数

JS 里有 `...args`（剩余参数）和 `arguments`。Python 对应的是 `*args` 和 `**kwargs`。

先记住它们的名字来源：

- `args` 是 arguments 的缩写，`*` 表示"把一堆位置参数收成一个**元组**"
- `kwargs` 是 keyword arguments 的缩写，`**` 表示"把一堆关键字参数收成一个**字典**"
- 名字 `args`、`kwargs` 只是**约定俗成**，不是语法要求。你可以叫 `*things`、`**opts`，但没人这么干，破坏共识。

看例子：

```python
def collect(*args, **kwargs):
    print("位置参数收到：", args)
    print("关键字参数收到：", kwargs)

collect(1, 2, 3, name="alice", age=20)
```

```text
位置参数收到： (1, 2, 3)
关键字参数收到： {'name': 'alice', 'age': 20}
```

`*args` 把三个位置参数收成了元组 `(1, 2, 3)`，`**kwargs` 把两个关键字参数收成了字典 `{'name': 'alice', 'age': 20}`。

### 它俩最典型的用途：转发

你写一个"包装函数"，不想管里面到底是什么参数，只想原样转发给另一个函数：

```python
def log_and_call(fn, *args, **kwargs):
    print(f"调用 {fn.__name__}，参数 {args} {kwargs}")
    return fn(*args, **kwargs)

def add(a, b):
    return a + b

print(log_and_call(add, 2, 3))
print(log_and_call(add, a=10, b=20))
```

```text
调用 add，参数 (2, 3) {}
5
调用 add，参数 () {'a': 10, 'b': 20}
30
```

`log_and_call` 自己完全不知道、也不关心 `add` 要什么参数，它只是"原样收下、原样转发"。
这个模式你在装饰器里会再见一次（3.11 节），因为装饰器本质上就是干这个的。

### 定义时的顺序有讲究

如果函数要同时用普通参数和 `*args`/`**kwargs`，顺序必须是：

```python
def f(a, b, *args, c=0, **kwargs):   # 位置 → *args → 关键字 → **kwargs
    pass
```

顺序记不住没关系，先记住两个铁律：

1. `*args` 必须在所有**位置参数**之后；
2. `**kwargs` 必须在所有**关键字参数**之后（也就是最末尾）。

> 一句话记住它：**`*args` 把多余位置参数收成元组，`**kwargs` 把多余关键字参数收成字典，二者配合就是"万能转发器"。**

## 3.5 参数解包：`*` 和 `**` 反过来用

3.4 节是"收"——把一堆参数收进元组/字典。这一节是"拆"——把现成的列表/字典拆开传给函数。

还是 `*` 和 `**`，但用在**调用时**：

```python
def add3(a, b, c):
    return a + b + c

nums = [1, 2, 3]
print(add3(*nums))     # 等于 add3(1, 2, 3)
```

```text
6
```

`*nums` 把列表 `[1, 2, 3]` 拆成三个位置参数 `1, 2, 3`。

字典用 `**` 拆，拆成关键字参数：

```python
def introduce(name, age):
    return f"{name} {age}"

info = {"name": "alice", "age": 20}
print(introduce(**info))   # 等于 introduce(name="alice", age=20)
```

```text
alice 20
```

注意 `**info` 拆出来的字典**键必须恰好匹配参数名**。键多一个、少一个、名字对不上，都会报错：

```python
info = {"name": "alice", "age": 20, "city": "beijing"}
print(introduce(**info))
```

```text
TypeError: introduce() got an unexpected keyword argument 'city'
```

### 一个特别常用的场景：`print` 解包

```python
values = [1, 2, 3]
print(*values)          # 等于 print(1, 2, 3)
print(values)           # 对比：直接传整个列表
```

```text
1 2 3
[1, 2, 3]
```

`print(*values)` 打印的是三个数，`print(values)` 打印的是带方括号的列表。前者就是解包的作用。

**记住口诀**：定义时 `*` 是"打包"，调用时 `*` 是"拆包"。同一个符号，两个方向。

> 一句话记住它：**调用时 `*列表` 拆成位置参数、`**字典` 拆成关键字参数，键必须对得上参数名。**

## 3.6 只位置参数 `/` 和只关键字参数 `*`

这一节是 Python 3.8 才补全的能力，面试偶尔考，日常也偶尔用，值得知道。

先给结论：**Python 允许你限制"某个参数只能用位置传"或"只能用关键字传"。**

看一个真实的函数签名——标准库里 `range`、`sorted` 其实就用了这些：

```python
def configure(host, /, port=80, *, debug=False):
    return host, port, debug
```

这里有两个特殊符号：

- `/` 左边的是**只位置参数**：只能 `configure("localhost")` 这样按位置传，不能 `configure(host="localhost")`。
- `*` 右边的是**只关键字参数**：只能 `configure(debug=True)` 这样按名字传，不能按位置塞。

```python
print(configure("localhost"))                      # host 按位置传
print(configure("localhost", 8080, debug=True))    # port 按位置，debug 必须按名字
```

```text
('localhost', 80, False)
('localhost', 8080, True)
```

### 为什么要这种限制？

**只位置参数**的场景：参数名没意义，或者将来想改名又不想破坏调用方。
比如 `abs(-3)` 你不可能写成 `abs(x=-3)`，`x` 这个参数名对调用者毫无信息量。用 `/` 把它锁死，你以后把 `x` 改名成 `value` 也不会影响任何调用者。

**只关键字参数**的场景：参数名本身就是文档，必须逼调用者写出来。
比如 `sorted(items, reverse=True)`，如果允许 `sorted(items, True)`，鬼知道这个 `True` 是啥。用 `*` 强制写成 `reverse=True`，调用处立刻可读。

破坏规则会报错：

```python
def configure(host, /, port=80, *, debug=False):
    return host

print(configure(host="localhost"))
```

```text
TypeError: configure() got some positional-only arguments passed as keyword arguments: 'host'
```

```python
def configure(host, /, port=80, *, debug=False):
    return host

print(configure("localhost", 80, True))
```

```text
TypeError: configure() takes 2 positional arguments but 3 were given
```

第一个报错说"只位置参数 `host` 被当关键字传了"，第二个说"只收 2 个位置参数但你给了 3 个"。
两条报错都很直白，就是字面意思。

> 一句话记住它：**`/` 锁死"只能按位置传"，`*` 锁死"只能按名字传"，本质是用语法强制调用处更可读、更稳定。**

## 3.7 作用域：LEGB 规则

到这一节，前面所有关于"参数"的事告一段落，进入本章第二个核心：**作用域**。

先给结论，再慢慢拆。Python 找变量，按 **L → E → G → B** 的顺序，一层层往外找：

| 字母 | 全称 | 含义 | 对应 JS 里的感觉 |
|---|---|---|---|
| **L** | Local | 当前函数内部 | 函数内的局部变量 |
| **E** | Enclosing | 外层函数（闭包） | 内层函数读外层函数的变量 |
| **G** | Global | 模块（文件）级别 | 顶层 `const` |
| **B** | Built-in | 内建命名空间（`len`、`print` 这些） | 全局对象上的原生函数 |

看一段代码，把四层全部串起来：

```python
x = "global"          # G 层：模块级变量

def outer():
    x = "enclosing"   # E 层：外层函数变量

    def inner():
        x = "local"   # L 层：内层函数自己的变量
        print(x)

    inner()

outer()
print(x)
```

```text
local
global
```

`inner()` 打印 `local`，因为它先在自己的 L 层找到了 `x`，就不再往外找了。最后一行打印 `global`，
因为那是在模块顶层执行的，它看到的 `x` 就是 G 层的。

**LEGB 的"找"是有顺序的**：先看自己函数里有没有，没有就看外层函数，再没有就看模块级，最后看内建。
**找到第一个就停，找不到就报 `NameError`。**

### 读和写，规则不一样（这是坑的根源）

上面的例子都是"读"变量。**读**遵循 LEGB 一路往外找。但**赋值**是另一套规则：

```python
x = "global"

def f():
    print(x)     # 先读，还没赋值
    x = "local"  # 这行让 x 变成了"局部变量"

f()
```

你猜会输出什么？按直觉，`print(x)` 应该先读到全局的 `"global"` 吧？

**真实结果是直接报错：**

```text
UnboundLocalError: cannot access local variable 'x' where it is not associated with a value
```

为什么？因为 Python 的规则是：**只要一个函数里对某个名字做了赋值，那么这个函数里这个名称从头到尾都被当作"局部变量"。**
所以 `print(x)` 里的 `x` 被当成局部变量，但此刻它还没被赋值（赋值在下一行），于是报 `UnboundLocalError`。

注意这条报错信息是 Python 3.11 之后的措辞。老版本（3.10 及以前）报的是
`UnboundLocalError: local variable 'x' referenced before assignment`。你网上搜到的旧报错，意思一模一样，只是说法变了。

**这跟 JS 完全不同。** JS 里 `var` 有变量提升（hoisting），`let` 有暂时性死区，行为各异。
Python 没有提升，规则就一条：**函数里赋值过 = 局部变量，从头到尾都是。**

### 那怎么改全局变量？

答案是 `global`，下一节和 `nonlocal` 一起讲。

> 一句话记住它：**Python 按 LEGB 从内往外找变量；但函数里只要对某名字赋过值，该名字就全程是局部变量，未赋值先读就报 `UnboundLocalError`。**

## 3.8 `global` 和 `nonlocal`

上一节的坑，解法就是显式声明"我要改外层的，不是新建局部的"。

### `global`：改模块级（G 层）变量

```python
count = 0

def bump():
    global count     # 声明：下面这个 count 是全局那个
    count += 1
    return count

print(bump())   # 1
print(bump())   # 2
print(count)    # 2
```

```text
1
2
2
```

没有 `global count` 这句，`count += 1` 会被当成"给局部变量赋值"，而 `+=` 要先读再写，
于是触发上一节那个 `UnboundLocalError`。加上 `global`，Python 就知道你要动的是全局那个。

### `nonlocal`：改外层函数（E 层）变量

`nonlocal` 解决的是另一个场景——**嵌套函数里改外层函数的变量**：

```python
def make_counter():
    count = 0
    def inc():
        nonlocal count   # 声明：改的是 make_counter 里的 count
        count += 1
        return count
    return inc

counter = make_counter()
print(counter())   # 1
print(counter())   # 2
print(counter())   # 3
```

```text
1
2
3
```

`nonlocal` 和 `global` 的区别，一句话就能记住：

- `global`：跳过所有层，直接改**模块级**变量；
- `nonlocal`：改**最近的一层外层函数**里的变量（不是全局）。

如果这里不用 `nonlocal`，改成 `global`，或者干脆不写，行为都不对，你可以自己试。

### 什么时候真的需要用它们？

说实话，**日常业务代码里，你几乎不该用 `global`。** 全局可变状态是万恶之源，函数最好"只靠参数输入、只靠返回值输出"（这叫纯函数）。
`nonlocal` 稍微常见一点，主要出现在"用闭包实现一个计数器/缓存"这种小场景里。

**把它们当成"我知道有这个逃生舱，但尽量别用"的工具。** 面试官问起，你答得出"它们分别是改全局和改闭包外层变量的"，就够了。

> 一句话记住它：**`global` 改模块级变量，`nonlocal` 改外层函数变量；能不用就不用，纯函数才是正道。**

---

## 3.9 闭包：函数记住了出生地

闭包（closure）是这一章最难也最重要的概念。先给一句大白话定义：

**闭包 = 一个函数，它"记住"了自己定义时所在环境里的变量，哪怕那个环境已经执行完了。**

看例子：

```python
def make_multiplier(n):
    def multiply(x):
        return x * n      # n 来自外层函数 make_multiplier
    return multiply       # 返回的是内层函数

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))   # 20
print(triple(10))   # 30
```

```text
20
30
```

`make_multiplier(2)` 执行完就返回了，按常理它的局部变量 `n` 应该"死了"。
但 `double(10)` 还能正确用到 `n=2`，`triple(10)` 用到 `n=3`。

**为什么？** 因为返回的 `multiply` 函数"记住"了 `n`。更准确地说：`multiply` 这个函数对象携带了一个
指向 `n` 的引用，只要 `double` 这个函数还活着，`n=2` 就不会被垃圾回收。

用官方术语说：**内层函数捕获（capture）了外层函数的自由变量。** "自由变量"指"不属于自己、来自外层环境的变量"。

### 为什么需要闭包？

闭包解决的核心问题是：**给函数"打包"一段状态，又不用污染全局。**

对比一下不用闭包的写法。你要两个不同的乘法器，用全局变量：

```python
n = 2
def double(x):
    return x * n

# 想要三倍的，只能再复制一份代码
def triple(x):
    return x * 3
```

这个写法有两个毛病：一是 `n` 是全局的，谁都能改；二是"三倍"得再写一遍，代码重复。
闭包把"配置"（`n`）和"逻辑"（`x * n`）焊在一起，每个闭包各带各的 `n`，互不干扰。

JS 里你其实见过一模一样的东西——`Array.map` 的回调闭包、`setTimeout` 里捕获变量，都是闭包。
所以你不是第一次见它，只是第一次用 `def` 写它。

### 一个直觉检验：闭包到底记了啥

看这个：

```python
def make_counter():
    count = 0
    def inc():
        nonlocal count
        count += 1
        return count
    return inc

c1 = make_counter()
c2 = make_counter()

print(c1())   # 1
print(c1())   # 2
print(c2())   # 1   ← c2 是另一个独立的 count
```

```text
1
2
1
```

`c1` 和 `c2` 各自有**独立**的 `count`。说明每次调用 `make_counter()` 都会产生一个全新的环境，
里面那个 `count` 是各论各的。这也是闭包最值钱的地方：**它像"为每个函数私造了一片独立的小天地"。**

> 一句话记住它：**闭包是"记住了出生地变量的函数"，它给函数打包一段私有状态，却不污染全局。**

## 3.10 闭包的晚绑定陷阱

闭包有个著名陷阱，面试必考，必须单独讲。

看这段代码，猜输出：

```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)   # 三个 lambda 都引用同一个 i

print([f() for f in funcs])
```

你八成以为输出 `[0, 1, 2]`。**真实输出是：**

```text
[2, 2, 2]
```

三个函数打印出来的全是 `2`。

### 为什么？因为闭包捕获的是"变量"，不是"值"

关键结论：**闭包捕获的是变量 `i` 本身，不是它当时的值。**

`for` 循环结束后，`i` 的值是 `2`。三个 lambda 都指向同一个变量 `i`，等真正调用它们时，
`i` 早就是 `2` 了，于是全都打印 `2`。

这跟 3.3 节"默认参数只求值一次"是同一个坑的不同侧面：**Python 的"绑定"发生在调用/执行的那一刻，而不是定义的那一刻。**

JS 里你踩过完全相同的坑——`for (var i = 0; ...) { setTimeout(() => console.log(i)) }` 打印的全是 3，
所以 JS 后来才出了 `let`（块级作用域）来治它。

### 解法一：默认参数"快照"

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])
```

```text
[0, 1, 2]
```

`lambda i=i: i` 里那个 `i=i` 是默认参数。回忆 3.3 节：默认参数在**定义时**就求值了，
于是每个 lambda 的默认参数 `i` 被当场"拍照"成了 `0`、`1`、`2`。等调用时，形参 `i` 优先用默认值，
于是各打各的。

### 解法二：再包一层函数

```python
def make_func(n):
    return lambda: n    # n 是 make_func 自己的局部变量，每次调用都是新的

funcs = [make_func(i) for i in range(3)]
print([f() for f in funcs])
```

```text
[0, 1, 2]
```

每次调用 `make_func(i)`，都会新建一个 `n`，这个 `n` 只属于这一次调用。三个 lambda 各捕获各的 `n`，互不干扰。

两种解法，**第一种更简洁，也是社区最常见的写法**，记住 `lambda i=i` 这个咒语就行。

> 一句话记住它：**闭包捕获的是变量不是值，循环里的 lambda 全指向同一个 `i`；用默认参数 `lambda i=i` 当场"快照"即可破解。**

## 3.11 装饰器（一）：本质是"接收函数返回函数"

现在进入本章的招牌：**装饰器（decorator）**。面试必考，框架里满屏都是，你必须彻底拿下。

先给它剥掉所有神秘感——**装饰器就是一个"接收一个函数、返回一个新函数"的高阶函数。** 就这一句。

回想 3.1 节的结论：函数是对象，能被传参、能被返回。装饰器只是把这个能力用到了极致：

```python
def log_call(fn):
    def wrapper(*args, **kwargs):
        print(f"调用 {fn.__name__}{args}")
        result = fn(*args, **kwargs)
        print(f"返回 {result}")
        return result
    return wrapper
```

`log_call` 接收函数 `fn`，返回一个新的函数 `wrapper`。`wrapper` 在调用 `fn` 前后各打印一行日志。
**这就是一个装饰器，没有任何魔法。**

### 手动套用：不用 `@` 也完全能跑

```python
def add(a, b):
    return a + b

wrapped_add = log_call(add)   # 把 add 包起来
print(wrapped_add(2, 3))
```

```text
调用 add(2, 3)
返回 5
5
```

看明白了吗？`log_call(add)` 返回了 `wrapper`，我们把它存进 `wrapped_add`，再调用它。
整个过程没有任何新语法，就是"函数传进去、函数返回来"。

### `@` 语法糖：只是上面的缩写

```python
@log_call
def add(a, b):
    return a + b

add(2, 3)
```

```text
调用 add(2, 3)
返回 5
```

`@log_call` 这行，**完全等价于** `add = log_call(add)`。没有别的，就是一句赋值。

所以装饰器的执行时机你也要清楚：**`@` 是在定义 `add` 那一刻就执行的**，不是等到调用 `add` 时才执行。
`add = log_call(add)` 发生在 `def add` 之后立刻，后面你调用的 `add` 其实已经是 `wrapper` 了。

### 为什么需要装饰器？

因为"给函数加功能"这件事，在真实项目里反复出现：打日志、计时、鉴权、缓存、重试……
如果不用装饰器，你会在每个函数里手写这些横切逻辑，或者复制粘贴一堆样板。

装饰器让你**把"横切逻辑"抽出来，用一行 `@` 贴到任意函数上**，被装饰的函数本身一行都不用改。

这就是"开闭原则"——对扩展开放（随时加装饰器），对修改封闭（原函数不动）。

> 一句话记住它：**装饰器是"接收函数返回函数"的高阶函数，`@deco` 只是 `fn = deco(fn)` 的语法糖。**

## 3.12 装饰器（二）：`functools.wraps` 保住元信息

上一节的装饰器有个隐藏 bug。先看现象：

```python
def log_call(fn):
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper

@log_call
def add(a, b):
    """把两个数加起来。"""
    return a + b

print(add.__name__)   # 你以为还是 add？
print(add.__doc__)    # 文档字符串呢？
```

```text
wrapper
None
```

`add.__name__` 变成了 `wrapper`，`add.__doc__` 变成了 `None`。

**为什么？** 因为 `@log_call` 等价于 `add = log_call(add)`，此时 `add` 这个名字已经指向 `wrapper` 了。
而 `wrapper` 的名字就是 `wrapper`，它没有文档字符串，所以 `add.__name__` 是 `wrapper`、`add.__doc__` 是 `None`。

**这有什么实际危害？** 三个真实场景：

1. **调试**：出异常时 traceback 显示的是 `wrapper`，你根本不知道真正出错的是哪个函数。
2. **自省工具**：Flask/FastAPI 靠函数名注册路由，名字变 `wrapper` 会直接冲突。
3. **文档生成**：Sphinx 这类工具读 `__doc__`，你写的文档全丢了。

### 解法：`functools.wraps`

标准库的 `functools.wraps` 干一件事：把原函数的 `__name__`、`__doc__` 等元信息，复制到 `wrapper` 上：

```python
import functools

def log_call(fn):
    @functools.wraps(fn)      # 关键就是这一行
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper

@log_call
def add(a, b):
    """把两个数加起来。"""
    return a + b

print(add.__name__)   # add
print(add.__doc__)    # 把两个数加起来。
```

```text
add
把两个数加起来。
```

`@functools.wraps(fn)` 本身也是个装饰器（你看，装饰器还能装饰装饰器）。
它的作用是：把 `fn` 的 `__name__`、`__doc__`、`__module__` 等一堆元信息，逐个复制给 `wrapper`。

### 铁律

**只要你写装饰器，就给它加 `@functools.wraps(fn)`。** 这是社区不成文的规矩，不加就等着在某个深夜被 traceback 里的 `wrapper` 气死。

> 一句话记住它：**装饰器会让函数丢失 `__name__`/`__doc__`，写装饰器必须加 `@functools.wraps(fn)` 把元信息复制回来。**

## 3.13 装饰器（三）：带参数的装饰器

前面的装饰器都是"无参"的：`@log_call` 直接贴。但有时你想给装饰器传参数，比如"重试 3 次"还是"重试 5 次"。

先想清楚一个逻辑：`@retry(3)` 这个写法里，`retry(3)` 是**先执行**的——它得先返回一个"真正的装饰器"，再让这个装饰器去装饰函数。

所以带参数的装饰器，是**三层嵌套**：

```python
def repeat(times):
    def decorator(fn):                     # 这才是"真正的装饰器"
        def wrapper(*args, **kwargs):
            return [fn(*args, **kwargs) for _ in range(times)]
        return wrapper
    return decorator                        # retry(3) 返回的就是这个 decorator

@repeat(3)
def say():
    return "hi"

print(say())
```

```text
['hi', 'hi', 'hi']
```

拆开看执行顺序：

1. `repeat(3)` 先执行，返回 `decorator`；
2. `@decorator` 再作用到 `say` 上，等价于 `say = decorator(say)`；
3. 最终 `say` 变成 `wrapper`，调用 `say()` 就执行三次 `fn()` 并把结果装进列表。

三层各干什么，一句话记住：

| 层 | 作用 | 接收什么 | 返回什么 |
|---|---|---|---|
| 最外层 | 接收装饰器的参数 | `times` | 真正的装饰器 |
| 中间层 | 接收被装饰的函数 | `fn` | 包装后的函数 |
| 最内层 | 接收调用参数 | `*args, **kwargs` | 真正的返回值 |

### 一个更贴近真实的例子：带重试次数的装饰器

```python
import time
import functools

def retry(times, delay=0.1):
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return fn(*args, **kwargs)
                except Exception as e:
                    if attempt == times - 1:
                        raise
                    time.sleep(delay)
        return wrapper
    return decorator

@retry(3)
def flaky():
    print("尝试一次")
    raise ValueError("暂时失败")

try:
    flaky()
except ValueError as e:
    print("最终失败：", e)
```

```text
尝试一次
尝试一次
尝试一次
最终失败： 暂时失败
```

`@retry(3)` 让 `flaky` 最多执行 3 次，每次都失败，最后把异常抛出来。这个例子里用到了 `functools.wraps`、
异常处理（第 05 章细讲）、`time.sleep`，你先把"三层结构"看明白就行。

> 一句话记住它：**带参数的装饰器是三层嵌套：外层收参数、中层收函数、内层收调用参数，`@deco(x)` 先算出"真装饰器"再装饰。**

## 3.14 `lambda`：一行匿名函数

JS 里箭头函数 `x => x * 2` 的 Python 对应物，是 `lambda`：

```python
square = lambda x: x * x
print(square(9))   # 81
```

```text
81
```

语法结构：`lambda 参数: 返回值表达式`。

跟 JS 箭头函数的区别，以及 Python 自己的限制，都在这张表里：

| 维度 | JS 箭头函数 | Python `lambda` |
|---|---|---|
| 语法 | `(x) => x * 2` | `lambda x: x * 2` |
| 能否写多行语句 | 能（`{...}`） | **不能**，只能一个表达式 |
| 能否赋值给变量 | 能 | 能 |
| 能否有 `return` | 显式或隐式 | **隐式**，表达式结果就是返回值 |
| 常用场景 | 回调 | `map`/`filter`/`sorted` 的 `key` |

**核心限制：`lambda` 只能是一个"表达式"，不能是"语句块"。** 你不能在里面写 `if...else...` 语句、
不能写 `for` 循环、不能写多行。要复杂逻辑，老老实实用 `def`。

这背后的哲学还是第 00 章那句"一件事最好只有一种明显正确的做法"：**简单到一行能表达的，用 `lambda`；
稍微复杂一点，就必须用 `def` 起个名字。** 起名字不是为了麻烦，是为了可读性。

### 什么时候用 `lambda`？

它最常见的归宿，是当"一次性、用完就扔"的小函数，喂给 `sorted` 的 `key`、`map`、`filter`：

```python
pairs = [("alice", 30), ("bob", 20), ("carol", 25)]
pairs.sort(key=lambda p: p[1])   # 按元组第二个元素（年龄）排序
print(pairs)
```

```text
[('bob', 20), ('carol', 25), ('alice', 30)]
```

这里 `lambda p: p[1]` 就是"给我元组，我返回它的第二个元素"，作为排序依据。这种小函数写个 `def` 太啰嗦，`lambda` 正合适。

> 一句话记住它：**`lambda` 是"只能一行表达式"的匿名函数，专用于 `key`、`map`、`filter` 这类一次性小函数，复杂的请用 `def`。**

## 3.15 `map` / `filter` / `reduce`

这三个是函数式编程的"老三样"，JS 里都有对应物（`Array.map`、`Array.filter`、`Array.reduce`）。
但 Python 的用起来有一个**关键差别**，先说结论：

**`map` 和 `filter` 返回的是"惰性迭代器"，不是列表。要看到结果，必须包一层 `list()`。**

先看 `map`：

```python
nums = [1, 2, 3, 4, 5]

doubled = map(lambda x: x * 2, nums)
print(doubled)               # 这不是列表！
print(list(doubled))         # 这才是列表
```

```text
<map object at 0x000001F3A2B1C0D0>
[2, 4, 6, 8, 10]
```

`doubled` 打印出来是 `<map object at ...>`，一个"惰性"对象——它不会立刻算完所有结果，而是等你真正需要时（比如 `list()`）才一个一个算。

`filter` 同理：

```python
nums = [1, 2, 3, 4, 5]

evens = filter(lambda x: x % 2 == 0, nums)
print(list(evens))   # [2, 4]
```

```text
[2, 4]
```

`filter` 只保留"返回真值"的元素。

### `reduce` 不一样：它不在内建里了

`map`/`filter` 是内建函数，直接用。但 `reduce` 从 Python 3 开始被"下放"到了 `functools` 模块，
得先 `import`：

```python
from functools import reduce

nums = [1, 2, 3, 4, 5]
total = reduce(lambda a, b: a + b, nums)
print(total)   # 15
```

```text
15
```

`reduce` 把列表"折叠"成一个值：第一次 `1+2` 得 `3`，再 `3+3` 得 `6`，一路折下去到 `15`。

### 为什么说"你其实不太需要它们"？

这是本章的一个诚实提醒：**在 Python 里，能用推导式就优先用推导式，`map`/`filter` 反而少见。**

对比一下：

```python
nums = [1, 2, 3, 4, 5]

# 用 map/filter
r1 = list(map(lambda x: x * 2, filter(lambda x: x % 2 == 0, nums)))

# 用推导式（更 Pythonic）
r2 = [x * 2 for x in nums if x % 2 == 0]

print(r1)
print(r2)
```

```text
[4, 8]
[4, 8]
```

结果一样，但 `r2` 明显更好读。所以社区共识是：**`map`/`filter` 知道就行，真写代码用推导式；`reduce` 更少见，大多数时候一个循环或 `sum()` 更清楚。**

它们存在的意义，更多是让你"看得懂别人写的函数式风格代码"，以及在某些纯函数式场景里配合使用。

> 一句话记住它：**`map`/`filter` 返回惰性迭代器要套 `list()`，`reduce` 要 `from functools import`；日常优先用推导式替代它们。**

## 3.16 `sorted` 的 `key`

排序是高频需求，`sorted` 是内建函数，几乎天天用。先看最基本的：

```python
nums = [3, 1, 4, 1, 5]
print(sorted(nums))                 # 升序，返回新列表
print(nums)                         # 原列表不动
print(sorted(nums, reverse=True))   # 降序
```

```text
[1, 1, 3, 4, 5]
[3, 1, 4, 1, 5]
[5, 4, 3, 1, 1]
```

`sorted` 返回一个**新列表**，原列表不变（对比 `list.sort()` 是原地改，返回 `None`，别搞混）。

### `key`：按"某个规则"排序

`key` 是 `sorted` 的灵魂。它接收一个函数，这个函数把每个元素"翻译"成排序用的键，然后按键排序：

```python
words = ["banana", "apple", "Cherry"]

print(sorted(words))                  # 默认按 Unicode 码点，大写排前面
print(sorted(words, key=str.lower))   # 先把每个词转小写再排
```

```text
['Cherry', 'apple', 'banana']
['apple', 'banana', 'Cherry']
```

为什么默认排序里 `Cherry` 排最前面？因为 `C` 的码点（67）比 `a`（97）小。加上 `key=str.lower`，
排序键变成 `banana`/`apple`/`cherry`，就按字母序排了。

**`key` 不改变原元素**——`str.lower` 只是用来"算排序依据"，最终输出的还是原来的 `"Cherry"`（大小写保留）。

### 最常用：按字典/元组的某个字段排

```python
users = [
    {"name": "alice", "age": 30},
    {"name": "bob", "age": 20},
    {"name": "carol", "age": 25},
]

by_age = sorted(users, key=lambda u: u["age"])
print([u["name"] for u in by_age])   # ['bob', 'carol', 'alice']
```

```text
['bob', 'carol', 'alice']
```

`key=lambda u: u["age"]` 就是"按每个字典的 `age` 字段排序"。这是后端开发里最常见的排序写法，
你会在"用户列表按注册时间排""商品按价格排"里反复见到。

再补一个冷知识：元组默认就能按"先第一个元素、再第二个元素"排序，有时候连 `key` 都不用写：

```python
pairs = [("b", 2), ("a", 3), ("a", 1)]
print(sorted(pairs))   # 先比第一个，再比第二个
```

```text
[('a', 1), ('a', 3), ('b', 2)]
```

> 一句话记住它：**`sorted` 返回新列表、原列表不动；`key` 是个函数，负责把元素翻译成"排序依据"，按字段排时写 `key=lambda x: x["字段"]`。**

## 3.17 生成器：`yield` 和 `yield from`

最后讲一个 JS 里也有、但 Python 里用得更狠的东西：**生成器（generator）**。

先给结论：**一个函数里只要出现了 `yield`，它就不再是普通函数，而是一个"生成器函数"。调用它不会执行函数体，而是返回一个生成器对象，你可以一个个地"要"出它的值。**

看最简单的：

```python
def count_up(n):
    i = 0
    while i < n:
        yield i        # 每次走到这，吐出一个值，然后"暂停"
        i += 1

gen = count_up(3)
print(gen)             # 不是 [0, 1, 2]，而是一个生成器对象
print(list(gen))       # 逼它把值都吐出来
```

```text
<generator object count_up at 0x000001F3A2B1C0D0>
[0, 1, 2]
```

对比普通函数，区别在哪？

| | 普通函数 `return` | 生成器函数 `yield` |
|---|---|---|
| 调用时机 | 调用就执行 | 调用只返回生成器，不执行 |
| 返回值 | 一个值，函数结束 | 可 `yield` 多个值，逐个吐 |
| 记忆状态 | 无 | **暂停时记住所有局部变量**，下次从暂停处继续 |

那个"暂停时记住状态"就是生成器的核心价值。它让"产生一个巨大的、甚至无限的序列"变成可能，而不必一次性全算出来占满内存。

### 为什么需要它？惰性 + 省内存

假设你要处理一个一亿行的日志文件。如果先 `list = [ ... ]` 把一亿行全读进内存，内存直接爆炸。
生成器的思路是：**要一行，算一行，给一行**，内存里永远只有当前这一行。

```python
def read_lines():
    yield "第1行"
    yield "第2行"
    yield "第3行"

for line in read_lines():
    print(line)
```

```text
第1行
第2行
第3行
```

`for` 循环天然会驱动生成器——每次循环体执行前，生成器就往下走一个 `yield`。
这就是为什么 Python 的 `for` 能遍历几乎任何东西：它背后靠的就是"迭代协议"，而生成器是最方便的实现方式（第 06 章讲 `async` 时还会用到同一套思路）。

### `yield from`：把另一个生成器"接"进来

当你想"生成器 A 里顺便把生成器 B 的值也吐出来"，用 `yield from`：

```python
def small():
    yield 1
    yield 2

def big():
    yield "start"
    yield from small()   # 把 small 的值一个个接进来
    yield "end"

print(list(big()))
```

```text
['start', 1, 2, 'end']
```

没有 `yield from`，你就得写一个 `for` 循环手动转发：

```python
def big():
    yield "start"
    for x in small():   # 老写法：手动遍历转发
        yield x
    yield "end"
```

`yield from` 就是这两行 `for ... yield` 的缩写，同时它还承担了"异常/返回值传递"等更细的活（进阶话题，先不展开）。

> 一句话记住它：**函数里出现 `yield` 就是生成器，调用只返回对象、不执行，靠惰性逐个吐值省内存；`yield from` 用来把别的生成器接进来。**

## 3.18 本章常见坑速查

| 坑 | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 可变默认参数 | `add_item("banana")` 返回 `['apple', 'banana']` | 默认参数在定义时只求值一次，`[]` 被所有调用共享 | 默认值用 `None`，函数体内再建 |
| 位置参数放关键字后面 | `SyntaxError: positional argument follows keyword argument` | 语法硬规则 | 位置参数一律写在关键字参数前面 |
| 同一参数传两次 | `TypeError: ... got multiple values for argument 'x'` | 位置和关键字各占一次 | 检查调用处，别重复传 |
| 函数里赋值又读取 | `UnboundLocalError: cannot access local variable 'x'...` | 赋值让名字全程变局部变量 | 要改全局用 `global`，改外层用 `nonlocal` |
| 闭包晚绑定 | 循环里的 lambda 全打印最后一个值 | 闭包捕获变量不是值 | 用默认参数 `lambda i=i` 快照 |
| 装饰器丢元信息 | `fn.__name__` 变成 `wrapper` | `@` 本质是 `fn = deco(fn)` | 加 `@functools.wraps(fn)` |
| 忘写 `nonlocal` | 计数器闭包报 `UnboundLocalError` | 闭包里 `count += 1` 被当成局部变量 | 声明 `nonlocal count` |
| `map`/`filter` 当列表用 | 打印出 `<map object at ...>` | 它们返回惰性迭代器 | 套 `list()` 或直接改用推导式 |
| `sorted` 原地改？ | 误以为原列表被排了 | `sorted` 返回新列表 | 记住 `sorted` 返回新列表，`list.sort()` 才是原地 |
| 生成器只能走一遍 | 第二次 `list(gen)` 是空 | 生成器是"一次性"的，吐完就耗尽 | 需要重用时重新调用生成器函数 |

## 3.19 本章小结

- **函数是一等公民对象**：能赋值、传参、返回，这是闭包和装饰器的地基。
- **参数分三种**：位置参数（按序）、关键字参数（按名）、默认参数（缺省用默认值）。
- **默认参数只在定义时求值一次**，所以永远别用可变对象当默认值，用 `None` 兜底。
- **`*args` 收多余位置参数成元组，`**kwargs` 收多余关键字参数成字典**，是万能转发器。
- **调用时 `*` 拆列表、`**` 拆字典**，键必须对得上参数名。
- **`/` 锁只位置、`*` 锁只关键字**，用语法强制调用处更可读。
- **作用域 LEGB**：Local → Enclosing → Global → Built-in，从内往外找。
- **函数里赋值过 = 全程局部变量**，未赋值先读报 `UnboundLocalError`；改全局用 `global`，改外层用 `nonlocal`。
- **闭包 = 记住了出生地变量的函数**，给函数打包私有状态，不污染全局。
- **闭包捕获变量不是值**，循环里的 lambda 要用 `lambda i=i` 快照破解晚绑定。
- **装饰器 = 接收函数返回函数**，`@deco` 是 `fn = deco(fn)` 的糖，写装饰器必加 `functools.wraps`。
- **带参装饰器是三层嵌套**：外层收参数、中层收函数、内层收调用参数。
- **`lambda` 只能一行表达式**，复杂逻辑用 `def`。
- **`map`/`filter` 惰性、`reduce` 在 `functools`**，日常优先推导式。
- **`sorted` 返回新列表**，`key` 函数负责翻译排序依据。
- **`yield` 让函数变生成器**，惰性吐值省内存，`yield from` 接别的生成器。

## 3.20 动手练习

1. 写一个函数 `safe_divide(a, b)`，当 `b` 为 0 时返回 `None`（而不是报错），否则返回 `a / b`。

   <details><summary>参考答案</summary>

   ```python
   def safe_divide(a, b):
       if b == 0:
           return None
       return a / b

   print(safe_divide(10, 2))   # 5.0
   print(safe_divide(10, 0))   # None
   ```

   </details>

2. 写一个装饰器 `timeit`，打印被装饰函数的执行耗时（用 `time.perf_counter()`），并保留原函数的 `__name__`。

   <details><summary>参考答案</summary>

   ```python
   import time
   import functools

   def timeit(fn):
       @functools.wraps(fn)
       def wrapper(*args, **kwargs):
           start = time.perf_counter()
           result = fn(*args, **kwargs)
           cost = time.perf_counter() - start
           print(f"{fn.__name__} 耗时 {cost:.6f} 秒")
           return result
       return wrapper

   @timeit
   def slow():
       time.sleep(0.01)
       return "done"

   print(slow())
   ```

   </details>

3. 用闭包实现一个"幂函数生成器" `make_power(n)`，返回一个函数，能算 `x ** n`。
   然后用它分别生成平方、立方两个函数，各算 `2` 的幂。

   <details><summary>参考答案</summary>

   ```python
   def make_power(n):
       def power(x):
           return x ** n
       return power

   square = make_power(2)
   cube = make_power(3)

   print(square(2))   # 4
   print(cube(2))     # 8
   ```

   </details>

4. 下面的代码会输出什么？为什么？如果你想让它输出 `[0, 1, 2]`，怎么改？

   ```python
   funcs = []
   for i in range(3):
       funcs.append(lambda: i)
   print([f() for f in funcs])
   ```

   <details><summary>参考答案</summary>

   输出 `[2, 2, 2]`。因为闭包捕获的是变量 `i` 而不是它的值，循环结束后 `i` 是 `2`，三个 lambda 都指向它。
   改成 `funcs.append(lambda i=i: i)` 即可，用默认参数在定义时"快照"住每个 `i`。

   </details>

5. 写一个生成器 `fib(n)`，逐个产出斐波那契数列的前 `n` 项（`0, 1, 1, 2, 3, 5, ...`），
   用 `list(fib(8))` 验证结果。

   <details><summary>参考答案</summary>

   ```python
   def fib(n):
       a, b = 0, 1
       for _ in range(n):
           yield a
           a, b = b, a + b

   print(list(fib(8)))   # [0, 1, 1, 2, 3, 5, 8, 13]
   ```

   </details>
