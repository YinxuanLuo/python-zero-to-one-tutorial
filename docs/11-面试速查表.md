## 第一部分 · 高频面试题 50 问

### 1. 数据类型与对象模型（10 题）

**Q1: 可变对象和不可变对象有什么区别？为什么这个区别重要？**

**答：可变对象（list、dict、set）创建后内容能改；不可变对象（int、str、tuple）每次"改"都产生新对象。这个区别直接决定了赋值、传参、可哈希性和默认参数行为。**

- 可变：`a = [1]; a.append(2)`，`a` 还是同一个对象，只是内容变了。
- 不可变：`s = "a"; s += "b"`，`s` 指向了全新的字符串，旧字符串被丢弃。
- 影响一：不可变对象可哈希，能作字典键、进 set；可变对象不行。
- 影响二：可变对象作为默认参数或共享引用时，容易被"意外修改"（见 Q15 的可变默认参数坑）。

**Q2: `is` 和 `==` 有什么区别？什么时候该用哪个？**

**答：`is` 比较对象身份（是不是同一个对象），`==` 比较值（相不相等）。比较值用 `==`，判断"是不是同一个"或"是不是 None"才用 `is`。**

- `a = [1,2]; b = [1,2]`：`a == b` 为 `True`，`a is b` 为 `False`。
- `is` 本质是 `id(a) == id(b)`，只比指针，不触发 `__eq__`，所以更快。
- 唯一公认的 `is` 用法是和 `None` 比：`x is None`，因为 `None` 是单例。
- 新手坑：`name is "admin"` 这种"碰巧能用"的代码，换一个字符串来源（文件、网络）就变 `False`。

**Q3: 浅拷贝和深拷贝有什么区别？分别怎么实现？**

**答：浅拷贝只复制最外层，嵌套对象仍共享；深拷贝递归复制所有层级。`copy.copy` 是浅拷贝，`copy.deepcopy` 是深拷贝。**

- 浅拷贝：`b = a.copy()`、`b = a[:]`、`copy.copy(a)`，改 `b` 里嵌套的可变对象会连累 `a`。
- 深拷贝：`copy.deepcopy(a)`，完全独立，代价是慢、遇到锁/文件句柄等不可复制对象会报错。
- 记忆：浅拷贝 = 复制一层皮，深拷贝 = 复制到底。
- 面试常追问：`deepcopy` 遇到循环引用（自己引用自己）也能处理，靠内部 memo 记录已复制对象。

**Q4: 列表和元组有什么区别？什么时候该用元组？**

**答：列表可变、元组不可变。元组用于"结构固定、不该被改"的数据，且能作字典键。**

- 元组可哈希，能作字典键、能进 set；列表不行。
- 元组比列表稍省内存、创建更快，但差异小，别当主要理由。
- 用元组的场景：函数多返回值、坐标 `(x, y)`、固定记录、常量表。
- 反例提醒：元组里的列表元素仍可变，`t = (1, [2])` 里 `t[1].append(3)` 合法。

**Q5: 什么是切片？`a[::-1]` 是干什么的？切片越界会报错吗？**

**答：切片用 `a[start:stop:step]` 取子序列，`a[::-1]` 是反转。切片越界不会报错（自动截断），但单个索引越界会报 `IndexError`。**

- `a[1:3]` 左闭右开，取下标 1、2；`a[::2]` 每两步取一个。
- 切片产生新对象，原序列不动；str/list/tuple 都支持切片。
- `a[100:200]` 越界返回空序列，不报错；`a[100]` 报 `IndexError: list index out of range`。
- 这是"切片宽容、索引严格"的设计，方便边界处理。

**Q6: 列表/字典/集合推导式分别怎么写？和普通循环比有什么优劣？**

**答：推导式是把"循环 + 过滤 + 变换"压进一行的语法糖。列表 `[x*2 for x in r if p]`、字典 `{k:v for ...}`、集合 `{x for ...}`。优点是可读、更快，缺点是太复杂时会牺牲可读性。**

- 列表推导式：`[x*2 for x in range(10) if x % 2 == 0]`。
- 字典推导式：`{k: k*2 for k in range(3)}`；集合推导式：`{x % 3 for x in range(10)}`。
- 推导式比等价的 `for + append` 通常更快（少一次函数调用开销）。
- 经验：一层推导式很优雅，两层以上就该拆成普通循环，别炫技。

**Q7: Python 里哪些类型是可哈希的？为什么字典的键必须可哈希？**

**答：所有不可变类型（int、str、tuple、frozenset）都可哈希，可变类型（list、dict、set）不可。字典靠哈希值定位键，键必须可哈希才能被稳定查找。**

- 可哈希的正式定义：对象有 `__hash__` 且在其生命周期内哈希值不变。
- 自定义对象默认可哈希（基于 `id`）；一旦你定义了 `__eq__` 而没定义 `__hash__`，它就变不可哈希。
- 元组可哈希的前提是它内部所有元素都可哈希：`(1, [2])` 不可哈希。
- 报错体验：`{[]: 1}` 抛 `TypeError: unhashable type: 'list'`。

**Q8: 字符串是不可变的，那 `s += "x"` 到底发生了什么？**

**答：它创建了一个全新的字符串对象并重新绑定到 `s`，原字符串没被修改，而是被丢弃。**

- `s = "a"; s += "b"` 后，`id(s)` 变了，说明是新对象。
- 代价：在循环里反复 `+=` 拼接长字符串是 O(n²)，会浪费大量内存。
- 正确做法：用 `"".join(parts)` 或把片段放进 list 最后 join。
- 这也是为什么 Python 不做 JS 那样的隐式类型转换——它逼你显式。

**Q9: `range(10)` 是什么对象？和 `list(range(10))` 有什么区别？**

**答：`range(10)` 是一个惰性的 `range` 对象，不真正存 10 个数；`list(range(10))` 才真正展开成列表。**

- `range` 是序列类型，支持索引、切片、`len`、`in`，但内存占用固定（只存 start/stop/step）。
- `range(10**9)` 几乎不占内存，而 `list(range(10**9))` 会爆内存。
- `range` 可以多次迭代，每次都是新的迭代器；这点和生成器不同。
- 判断类型：`type(range(3))` 是 `<class 'range'>`，不是 list。

**Q10: 什么是解包（unpacking）？`a, *b = [1, 2, 3, 4]` 会得到什么？**

**答：解包是把一个可迭代对象拆开赋值给多个变量；`a, *b = [1, 2, 3, 4]` 得到 `a=1`、`b=[2, 3, 4]`。**

- 普通解包：`a, b = 1, 2`；交换值：`a, b = b, a`。
- 星号解包 `*b` 把剩余元素收成一个列表；`a, *b, c = [1,2,3,4]` 得 `a=1, b=[2,3], c=4`。
- 反向的 `*` 用于展开实参：`f(*[1,2])` 等价 `f(1,2)`。
- 数量不匹配会报 `ValueError: too many values to unpack`。

### 2. 函数与作用域（8 题）

**Q11: 什么是 LEGB 作用域规则？**

**答：查找变量按 Local（函数内）→ Enclosing（外层闭包）→ Global（模块）→ Built-in（内建）的顺序，先找到先用。**

- Local：当前函数内部定义的变量。
- Enclosing：嵌套函数的外层作用域，闭包读的就是它。
- Global：模块顶层；Built-in：`len`、`print` 等内建名字。
- 关键区分：**读**变量走 LEGB；**赋值**默认在当前作用域创建新变量，想改外层要 `global`/`nonlocal`。

**Q12: 什么是闭包？它解决了什么问题？**

**答：闭包是"函数 + 它定义时捕获的环境变量"，让函数离开定义它的作用域后仍能访问那些变量。**

- 典型例子：`make_counter` 返回 `inc`，`inc` 记住了 `count`。
- 作用：不引入类就能保存状态、做延迟执行、给装饰器提供配置。
- 关键：捕获的是变量的引用（不是值快照），所以改外层要 `nonlocal`。
- 和 JS 闭包是同一套概念，你有 JS 基础应该秒懂。

**Q13: `global` 和 `nonlocal` 有什么区别？**

**答：`global` 声明变量是模块级全局变量，`nonlocal` 声明变量是最近的外层（闭包）变量。**

- `global x`：函数内给 `x` 赋值时改的是模块全局的 `x`。
- `nonlocal x`：改的是**最近一层非局部**的 `x`（不能是全局，只能是闭包层）。
- 只在"要赋值"时才需要；只读不需要声明。
- 滥用 `global` 是坏味道，通常是设计问题（应该传参或返回）。

**Q14: 星号参数 `*args` 和双星号参数分别收集什么？能接受什么调用？**

**答：`*args` 把多余的位置参数收成元组，`**kwargs` 把多余的关键字参数收成字典；合起来能接受任意调用方式。**

- `f(1, 2, a=3)` 会得到 `args=(1, 2)`、`kwargs={'a': 3}`。
- 反向解包：`f(*[1,2])` 等价 `f(1,2)`，`f(**{"a":1})` 等价 `f(a=1)`。
- 真正起作用的是 `*` 和 `**`，`args`/`kwargs` 只是约定名。
- 典型用途：装饰器里 `wrapper(*args, **kwargs)` 透传参数。

**Q15: 为什么默认参数不要用可变对象？正确的写法是什么？**

**答：默认参数在函数**定义时**只求值一次，可变对象会被所有调用共享、越攒越多；正确写法是默认 `None`，进函数再创建。**

```python
def f(items=None):
    if items is None:
        items = []
    items.append(1)
    return items
```

- 坑的根源：默认值在 `def` 执行那一刻就固定了，不是每次调用时新建。
- 对 int/str/None 这类不可变对象无影响，因为改了也是新对象。
- 面试官常让你现场演示两次 `f()` 的结果，答不出来说明没真写过 Python。

**Q16: Python 函数传参是值传递还是引用传递？**

**答：准确说是"按对象引用传递"（call by object reference / 传对象引用）。传的是对象的引用，但函数内对参数的重新赋值不影响调用方变量。**

- 传可变对象：函数内**改它的内容**（如 `lst.append`）会影响到调用方，因为是同一个对象。
- 传不可变对象或**重新赋值**（如 `x = 5`）：不影响调用方，因为只是让形参指向了新对象。
- 所以严格说既不是 C 的值传递，也不是 C++ 的引用传递，而是"传引用，但赋值是局部的"。
- 面试加分句：Python 不区分"传值/传引用"，它只做一件事——把实参对象绑定到形参名上。

**Q17: 什么是 lambda？它和 `def` 有什么区别？**

**答：lambda 是"单表达式匿名函数"，只能写一个表达式、不能有语句；`def` 是有名字、可多语句的完整函数。**

- `lambda x: x * 2` 等价于 `def f(x): return x * 2`。
- lambda 不能有 `return`、不能有多行、不能有类型标注语句块。
- 典型用途：`sorted(items, key=lambda x: x['age'])`、`map`/`filter` 的短回调。
- 函数式编程风格里，lambda 是"用完即扔"的小函数；复杂逻辑还是用 `def`。

**Q18: 什么是生成器？`yield` 是干什么的？**

**答：生成器是一种惰性迭代器，函数里出现 `yield` 它就变成生成器函数；`yield` 产出一个值并暂停，下次从暂停处继续。**

- 调用生成器函数不执行函数体，返回一个生成器对象。
- 每次 `next()` 或 `for` 迭代，跑到下一个 `yield` 并返回值。
- 好处：内存友好，适合处理大文件、无限序列、流式数据。
- 和列表的区别：列表一次性算完占内存，生成器按需算、只能消费一次。

### 3. 装饰器与元编程（6 题）

**Q19: 装饰器是什么？它的原理是什么？**

**答：装饰器是接收一个函数、返回一个新函数的高阶函数；`@deco` 就是 `func = deco(func)` 的语法糖。**

- 原理：`wrapper` 里做前置/后置逻辑 → 调用原函数 → 返回结果。
- 典型用途：计时、日志、鉴权、缓存、重试。
- 必须加 `functools.wraps` 保住原函数元数据（`__name__`、`__doc__`）。
- 装饰器在**定义时**就执行（不是调用时），`@deco` 那行代码跑的时候就把函数替换了。

**Q20: 写装饰器为什么必须加 `functools.wraps`？**

**答：因为装饰后函数名指向的是 `wrapper`，不加 `wraps` 会丢失原函数的 `__name__`、`__doc__` 等元数据，影响调试、日志和文档工具。**

```python
from functools import wraps

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        ...
    return wrapper
```

- 不加的话 `fetch_data.__name__` 变成 `"wrapper"`，`__doc__` 变成 `None`。
- `wraps` 内部用 `functools.update_wrapper` 把原函数的元数据拷贝过去。
- 任何"包一层"的场景（装饰器、代理）都要考虑元数据保真。

**Q21: 带参数的装饰器怎么实现？**

**答：要多包一层"装饰器工厂"——外层函数接收配置参数，返回真正的装饰器。**

```python
def repeat(n):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(n):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def greet():
    print("hi")
```

- 记忆：`@repeat(3)` 先调用 `repeat(3)` 得到 `decorator`，再用它装饰函数，等价 `greet = repeat(3)(greet)`。
- 关键是想清楚"外层负责传参、中层负责装饰、内层负责包装"三层结构。

**Q22: 多个装饰器的执行顺序是怎样的？**

**答：装饰顺序从下往上（靠近函数的最先执行），运行时则从外往里进入、从里往外返回。**

```python
@a
@b
def f():
    pass
# 等价于 f = a(b(f))
```

- 定义阶段：先 `b(f)`，再 `a(b(f))`。
- 调用阶段：先进入 `a` 的 wrapper，再进入 `b` 的 wrapper，最后才执行 `f` 本体。
- 面试记忆：**装饰器像穿衣服，越靠近函数的越先穿、越靠外。**

**Q23: 类装饰器和函数装饰器有什么区别？**

**答：函数装饰器装饰函数，类装饰器装饰类；类装饰器接收一个类、返回一个类（或函数），常用于给类批量加方法或属性。**

```python
def add_greeting(cls):
    cls.greet = lambda self: f"hi, {self.name}"
    return cls

@add_greeting
class User:
    def __init__(self, name):
        self.name = name
```

- 函数装饰器：`@deco` 后 `f` 变成 `deco(f)` 的返回值。
- 类装饰器：`@deco` 后 `User` 变成 `deco(User)` 的返回值，可用来注册类、注入方法。
- 另一种"类做装饰器"：类实现 `__call__`，实例可当装饰器用（能保存状态）。

**Q24: 装饰器有哪些典型应用场景？**

**答：横切关注点（cross-cutting concerns）——日志、计时、缓存、鉴权、重试、参数校验、事务，这些"和业务无关但每个函数都要做"的事。**

- 日志/埋点：统一打印入参、出参、耗时。
- 缓存：`functools.lru_cache` 是标准库内置的记忆化装饰器。
- 鉴权：Web 框架里 `@login_required`。
- 重试：网络请求失败自动重试 N 次。
- 共同点：把"重复的样板逻辑"从业务函数里抽出来，一次写、处处用。

### 4. 类与对象模型（8 题）

**Q25: 什么是鸭子类型？它和静态类型冲突吗？**

**答：鸭子类型是"看它会不会 `quack()`，不看它是不是 `Duck`"——只关心对象有没有需要的方法，不检查类型。它和静态类型是互补的，类型标注 + mypy 可以在不改变运行时鸭子类型的前提下补静态检查。**

- 例子：`def read_all(f): return f.read()` 不检查 `f` 类型，只要有 `.read()` 就行。
- 好处：灵活、少样板、易于 mock 和替换实现。
- 代价：类型错误推迟到运行时才暴露。
- 它体现的是 Python 哲学"看你会什么，不看你是什么"。

**Q26: `self` 是什么？为什么每个方法都要写？**

**答：`self` 是实例方法第一个参数，指向调用它的那个实例；它让方法能访问实例的属性。它不是关键字，是约定俗成的名字。**

- `obj.method(x)` 等价于 `Class.method(obj, x)`，`obj` 被自动传成 `self`。
- 名字可以换（写 `this` 也能跑），但全社区都用 `self`，别特立独行。
- 类方法第一个参数是 `cls`（指向类），静态方法没有 `self`/`cls`。
- 这是 Python 把"显式优于隐式"贯彻到极致的例子：连实例引用都要你自己写。

**Q27: `__init__` 和 `__new__` 有什么区别？**

**答：`__new__` 负责**创建**实例并返回，`__init__` 负责**初始化**已创建的实例；`__new__` 先执行，`__init__` 后执行。**

- 99% 场景你只写 `__init__`，`__new__` 默认从 `object` 继承。
- `__new__` 用在单例、不可变类型（如 tuple/str）的定制、元编程。
- `__new__` 是静态方法（虽然不用显式写），第一参数是 `cls`。
- 面试加分点：单例模式可用 `__new__` 实现，`__init__` 每次实例化都会调用（所以单例里要小心重复初始化）。

**Q28: 什么是魔术方法？常用的有哪些？**

**答：魔术方法（dunder methods）是以双下划线开头结尾的特殊方法，让对象支持运算符、内建函数和语言协议。常用：`__init__`、`__str__`/`__repr__`、`__eq__`、`__len__`、`__getitem__`。**

- `__init__`：初始化；`__str__`：`print(obj)` 时的人性化输出；`__repr__`：调试用、可还原的表示。
- `__eq__`：定义 `==` 的行为，不定义默认比身份。
- `__len__`：让对象支持 `len(obj)`；`__getitem__`：让对象支持 `obj[key]` 和切片。
- `__enter__`/`__exit__`：让对象支持 `with` 语句。
- 好处：让你的类"融入"语言，像内置类型一样被使用。

**Q29: 什么是 MRO？`super()` 是怎么工作的？**

**答：MRO（Method Resolution Order）是多重继承时方法查找的顺序，Python 用 C3 线性化算法算出；`super()` 沿 MRO 找"当前类之后的下一个类"的实现。**

- 查看：`类名.__mro__` 或 `类名.mro()`。
- `super()` 不是"找父类"，而是"按 MRO 顺序找下一个"，所以钻石继承也能正确调用。
- 钻石继承 `D(B, C)` 且 `B/C(A)` 时，C3 保证 `A` 只被初始化一次。
- 无法线性化的冲突继承会抛 `TypeError`，这是 C3 的保护机制。

**Q30: `@property` 是干什么的？和直接暴露属性有什么区别？**

**答：`@property` 把方法变成"像属性一样访问"，让你在读取/赋值时插入逻辑（校验、计算、日志），同时保持 `obj.attr` 的简洁语法。**

```python
class Circle:
    def __init__(self, r):
        self._r = r
    @property
    def area(self):
        return 3.14159 * self._r ** 2
```

- 直接暴露属性的问题：以后想加校验/计算就得改所有调用点。
- `@property` 能"看起来是属性、背后是方法"，是封装和易用的平衡。
- 还有 `@x.setter`、`@x.deleter` 处理赋值和删除。
- 好处：先暴露属性，以后需要逻辑时再无缝改成 property，调用方无感。

**Q31: `__slots__` 是什么？什么时候该用？**

**答：`__slots__` 显式声明实例允许有哪些属性，省去每个实例的 `__dict__`，从而省内存、稍加快属性访问。**

```python
class Point:
    __slots__ = ('x', 'y')
    def __init__(self, x, y):
        self.x = x
        self.y = y
```

- 代价：不能动态加新属性（`p.z = 1` 报 `AttributeError`）。
- 只在"海量小对象"时收益明显（比如上百万个点），普通类用它是过早优化。
- 注意：`__slots__` 里的名字也会屏蔽类属性；要保留弱引用支持需加 `__weakref__`。
- 面试加分句：普通业务类别用 `__slots__`，它牺牲灵活性换的那点内存，绝大多数场景不值。

**Q32: 类变量和实例变量有什么区别？**

**答：类变量定义在类体里、被所有实例共享；实例变量定义在 `self` 上、每个实例各有一份。**

```python
class Dog:
    species = "犬科"      # 类变量
    def __init__(self, name):
        self.name = name  # 实例变量
```

- 读时：`dog.species` 若实例没有同名属性，会回退到类变量。
- 写时：`dog.species = "猫科"` 会**给实例新建**实例变量，而不是改类变量。
- 改类变量要用 `Dog.species = ...`。
- 坑：用可变对象做类变量（如 `class A: items = []`）会被所有实例共享，改一个全变。

### 5. 异常与上下文管理器（6 题）

**Q33: Python 的异常层次是怎样的？`Exception` 和 `BaseException` 有什么区别？**

**答：所有异常都继承自 `BaseException`；`Exception` 是 `BaseException` 的子类。业务/普通异常继承 `Exception`，`KeyboardInterrupt`、`SystemExit`、`GeneratorExit` 直接继承 `BaseException` 而不属于 `Exception`。**

- 层次：`BaseException` → `Exception` → 各种具体异常（`ValueError`、`TypeError`、`KeyError`...）。
- 捕获业务异常写 `except Exception`，别写 `except BaseException`（会把 Ctrl+C、`sys.exit()` 也吞掉）。
- `ZeroDivisionError` 是 `ArithmeticError` 的子类，`ArithmeticError` 是 `Exception` 的子类。
- 面试加分：能说出"为什么要区分"，因为系统级异常不该被业务代码拦截。

**Q34: `try/except/else/finally` 的执行顺序是怎样的？**

**答：先执行 `try`；无异常走 `else`；有异常匹配 `except`；无论有无异常，`finally` 最后一定执行。**

- `else` 只在 `try` **没有**异常时执行，常放"成功后的收尾"代码。
- `finally` 一定执行（即使 `except` 里又抛了异常、或 `return` 了），常放清理资源。
- `finally` 里的 `return` 会覆盖前面的返回值，是经典坑。
- 记忆：`try` 干活，`except` 兜错，`else` 成功后处理，`finally` 善后。

**Q35: 为什么不应该写裸的 `except:`？**

**答：`except:` 不带类型会捕获一切异常，包括 `KeyboardInterrupt`（用户 Ctrl+C）、`SystemExit` 和程序 bug，把该崩的问题静默吞掉，难以排查。**

- 应该写具体类型：`except ValueError:`，或兜底写 `except Exception:`。
- 兜底时最好记录异常：`except Exception as e: log(e); raise`，不要默默吞。
- 常见错误：`except:` 里只 `pass`，等于埋一颗"线上偶发、查无实据"的雷。
- 原则：**捕获你预期能处理的异常，其余让它往上抛**。

**Q36: 自定义异常怎么做？什么时候需要自定义异常？**

**答：继承 `Exception`（或更具体的子类），起个有意义的名字；当你想让"错误类型本身携带业务含义、能被精确捕获"时自定义。**

```python
class InsufficientFundsError(Exception):
    def __init__(self, balance, amount):
        self.balance = balance
        self.amount = amount
        super().__init__(f"余额 {balance} 不足，无法扣款 {amount}")
```

- 好处：调用方能 `except InsufficientFundsError:` 精确捕获，而不是靠解析字符串。
- 自定义异常可以带额外字段（余额、金额），方便排查。
- 命名以 `Error` 结尾，符合社区惯例。

**Q37: `with` 语句的原理是什么？怎么自定义上下文管理器？**

**答：`with` 调用对象的 `__enter__` 和 `__exit__`，保证资源在离开时被释放（即使有异常）。自定义只需实现这两个方法，或用 `contextlib.contextmanager` 装饰器。**

```python
class Managed:
    def __enter__(self):
        print("进入")
        return self
    def __exit__(self, exc_type, exc, tb):
        print("退出，无论有没有异常")
        return False   # False = 不吞异常
```

- `__enter__` 的返回值赋给 `with ... as x` 里的 `x`。
- `__exit__` 返回 `True` 会吞掉异常，返回 `False`（或 `None`）则异常继续传播。
- 更简洁的方式：`@contextlib.contextmanager` 把一个 `yield` 的生成器函数变成上下文管理器。
- 典型应用：文件、数据库连接、锁、临时目录的自动清理。

**Q38: 什么是 `raise ... from ...`？异常链有什么用？**

**答：`raise NewError(...) from original` 在抛出新异常的同时保留原始异常作为"原因"，形成异常链；它用于"捕获低层异常、包装成高层异常"时不丢失根因。**

```python
try:
    result = db.query(...)
except DBError as e:
    raise ServiceError("查询失败") from e
```

- 不写 `from` 时，Python 会**隐式**把当前异常链到新异常上（`__context__`）。
- 显式 `from e` 设置的是 `__cause__`，`from None` 则刻意切断链（隐藏低层细节）。
- 排查时看 traceback 会显示 "The above exception was the direct cause of..."。
- 价值：向上层抛出业务异常的同时，保留原始技术细节供调试。

### 6. 并发、类型标注与内存管理（12 题）

**Q39: GIL 是什么？它对多线程有什么影响？**

**答：GIL（Global Interpreter Lock）是 CPython 的全局解释器锁，同一时刻只允许一个线程执行 Python 字节码；它让多线程在 CPU 密集任务上无法真并行，但 I/O 密集不受影响。**

- GIL 存在的原因：简化 CPython 的内存管理和引用计数，避免并发改对象。
- CPU 密集：多线程不但不快，切换开销反而更慢。
- I/O 密集：线程在等待 I/O 时会释放 GIL，多线程依然能提升吞吐。
- 注意：GIL 是 CPython 的实现细节，Jython、PyPy 等实现没有（或不同）。

**Q40: 线程、进程、协程（asyncio）有什么区别？分别适合什么场景？**

**答：线程共享内存、受 GIL 限制、适合 I/O 密集；进程内存隔离、能真正并行、适合 CPU 密集；协程是单线程内的协作式调度、开销最小、适合海量 I/O 并发。**

- 线程：`threading`，切换由系统调度，创建/切换开销中等。
- 进程：`multiprocessing`，绕开 GIL 实现多核并行，但通信要序列化，开销大。
- 协程：`asyncio`，单线程事件循环，`await` 处让出控制权，几乎零切换开销。
- 一句话选择：**CPU 密集用进程，I/O 密集用线程或 asyncio，海量并发 I/O 用 asyncio。**

**Q41: CPU 密集任务和 I/O 密集任务分别该用什么方案？**

**答：CPU 密集（大量计算）用 `multiprocessing` 多进程并行；I/O 密集（等网络/磁盘）用线程或 `asyncio`，海量并发选 `asyncio`。**

- CPU 密集用线程没用：GIL 让它们串行，反而更慢。
- I/O 密集用进程浪费：进程开销大、通信成本高。
- 经验：网络爬虫、Web 服务（I/O 密集）→ asyncio；图像处理、科学计算（CPU 密集）→ 多进程或 NumPy（释放 GIL 的 C 扩展）。
- 补充：很多重计算库（NumPy/Pandas）内部是 C，会释放 GIL，此时多线程也能并行。

**Q42: `asyncio` 的事件循环是怎么工作的？**

**答：事件循环是一个单线程的调度器，维护一个任务队列，循环地从队列取出就绪的协程执行，遇到 `await` 的 I/O 就把控制权交还循环、去跑别的任务。**

- 核心：协程在 `await` 处主动让出，事件循环切换到下一个可运行任务。
- 没有线程切换的开销，也没有锁竞争，所以能轻松支撑上万并发连接。
- `await asyncio.sleep(1)` 不是阻塞线程，而是"挂起当前协程、1 秒后再唤醒"。
- 关键约束：协程里不能有阻塞调用（如 `time.sleep`、同步的网络请求），否则整个循环被卡死。

**Q43: `async` / `await` 是什么？和线程的阻塞有什么区别？**

**答：`async` 定义协程函数，`await` 挂起当前协程等待另一个协程完成；它是"协作式让出"，不阻塞线程，而线程的阻塞会占住线程资源。**

- `async def f()` 调用不执行、返回一个协程对象，要用 `await f()` 或 `asyncio.run(f())`。
- `await` 处协程让出控制权，事件循环去跑别的任务，等结果回来再恢复。
- 线程阻塞是"站着等"，协程是"让位等别人先干"。
- 协程内出现阻塞调用会让整个事件循环卡住，这是最常见的 asyncio 事故。

**Q44: 类型标注（type hint）有什么用？它会影响运行时吗？**

**答：类型标注声明变量/参数的预期类型，用于静态检查、IDE 补全和文档；它在运行时**不生效**，不影响性能。**

```python
def greet(name: str) -> str:
    return "hi " + name
```

- 运行时标注只是函数的 `__annotations__` 属性，解释器不检查。
- 真正检查靠 `mypy` 这类静态工具，在运行前跑。
- 好处：IDE 自动补全、重构安全、作为"可执行的文档"。
- 注意：标注不会让代码变慢，也不会阻止传错类型——它只是给工具看的。

**Q45: `mypy` 是干什么的？和运行时的类型检查有什么区别？**

**答：`mypy` 是 Python 的静态类型检查器，在**运行前**根据类型标注分析代码，找出类型错误；运行时的类型检查是程序跑起来后才按实际对象类型报错。**

- 用法：`pip install mypy`，然后 `mypy your_file.py`。
- 静态检查能提前发现"传错类型"这类 bug，但不影响运行时行为。
- 运行时检查靠 `isinstance`、鸭子类型、异常等，是真实发生的。
- 两者互补：静态检查挡"明显错误"，运行时边界（外部输入）仍要自己校验。

**Q46: Python 的垃圾回收机制是怎样的？**

**答：CPython 以引用计数为主，用"标记-清除"和"分代回收"处理循环引用。**

- 引用计数：对象被引用数 +1，引用解除 -1，归零立即回收（`del`、离开作用域）。
- 循环引用（A 引用 B、B 引用 A）让引用计数永远不为零，靠标记-清除兜底。
- 分代回收：对象按存活时间分 0/1/2 三代，年轻代更频繁扫描。
- 可用 `sys.getrefcount(obj)` 看引用计数，`gc.collect()` 手动触发回收。

**Q47: 什么是循环引用？Python 怎么处理它？**

**答：循环引用是两个或多个对象互相引用，导致引用计数永远不为零；Python 的 gc 模块用"标记-清除"找到不可达的循环并回收。**

```python
a = []
b = []
a.append(b)
b.append(a)   # 循环引用
del a, b      # 引用计数不为 0，但已不可达
```

- 单靠引用计数解决不了，所以 CPython 有 gc 兜底。
- 有 `__del__` 的对象在循环引用里可能永远不被回收（`gc.garbage`），这是坑。
- 显式打破循环：用完设 `None`，或用 `weakref` 弱引用。
- 大多数场景不用手动干预，gc 会自动处理。

**Q48: 什么是引用计数？它有什么优缺点？**

**答：引用计数是每个对象记录"有多少引用指向它"，归零立即回收。优点是及时、确定；缺点是有循环引用问题和原子操作开销。**

- 优点：对象一不可达就立即释放，内存不堆积；GC 停顿小。
- 缺点：每次赋值/传参都要增减计数，有性能开销（这是 GIL 存在的部分原因）。
- 缺点：循环引用解决不了，需要 gc 辅助。
- 看计数：`sys.getrefcount(x)`（结果比预期多 1，因为传入时又加了一次）。

**Q49: 如何优化 Python 程序的内存和性能？**

**答：先 profile 找到瓶颈（别瞎优化），再用针对手段：I/O 用 asyncio/连接池、CPU 密集用多进程或 C 扩展、内存用生成器/`__slots__`/及时释放。**

- 测瓶颈：`cProfile`、`timeit`、`memory_profiler`，先定位再动手。
- CPU：多进程、NumPy 向量化、必要时 Cython/C 扩展。
- I/O：asyncio、连接池、批量操作。
- 内存：大文件逐行读、生成器代替列表、`__slots__` 省对象、及时 `del` 大对象。
- 通用：缓存结果（lru_cache）、避免循环里重复计算、用内置函数（C 实现比纯 Python 快）。

**Q50: `dataclasses` 是什么？它解决了什么问题？**

**答：`dataclasses` 装饰器自动生成 `__init__`、`__repr__`、`__eq__` 等样板方法，让"存数据的类"几行写完，专治写 `__init__` 的重复劳动。**

```python
from dataclasses import dataclass

@dataclass
class User:
    name: str
    age: int = 0
```

- 自动生成 `__init__`、`__repr__`、`__eq__`，可配置是否可变、是否排序。
- `frozen=True` 得到不可变数据类（可哈希，能作字典键）。
- 对比：普通类写这些样板要十几行，dataclass 一行搞定。
- 适用：DTO、配置对象、返回模型；不适用：有复杂行为的领域对象。

### 2.1 手写实现（10 题）

**题 1：写一个计时器装饰器** —— 思路：`functools.wraps` 包一层，`time.time()` 前后取差。

```python
import time
from functools import wraps

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时 {time.time() - start:.3f}s")
        return result
    return wrapper
```

**题 2：写一个带参数的装饰器（repeat n 次）** —— 思路：三层结构，外层收参数、中层返回装饰器、内层包装。

```python
from functools import wraps

def repeat(n):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(n):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator
```

**题 3：写一个闭包计数器** —— 思路：内层函数捕获 `count`，`nonlocal` 声明修改。

```python
def make_counter():
    count = 0
    def inc():
        nonlocal count
        count += 1
        return count
    return inc
```

**题 4：用 `OrderedDict` 手写 LRU 缓存** —— 思路：访问时 `move_to_end`，超容量 `popitem(last=False)`。

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.data = OrderedDict()

    def get(self, key):
        if key not in self.data:
            return -1
        self.data.move_to_end(key)
        return self.data[key]

    def put(self, key, value):
        if key in self.data:
            self.data.move_to_end(key)
        self.data[key] = value
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)
```

**题 5：递归实现深拷贝** —— 思路：按类型分派，`list`/`dict`/`tuple`/`set` 递归，其余直接返回。

```python
def deep_copy(obj):
    if isinstance(obj, list):
        return [deep_copy(x) for x in obj]
    if isinstance(obj, dict):
        return {k: deep_copy(v) for k, v in obj.items()}
    if isinstance(obj, tuple):
        return tuple(deep_copy(x) for x in obj)
    if isinstance(obj, set):
        return {deep_copy(x) for x in obj}
    return obj
```

**题 6：记忆化装饰器（memoize）** —— 思路：字典缓存，`args` 元组当键，`@wraps` 保元数据。

```python
from functools import wraps

def memoize(func):
    cache = {}
    @wraps(func)
    def wrapper(*args):
        if args not in cache:
            cache[args] = func(*args)
        return cache[args]
    return wrapper
```

**题 7：展平嵌套列表（flatten）** —— 思路：递归展开 `list`，非列表直接收集。

```python
def flatten(items):
    result = []
    for item in items:
        if isinstance(item, list):
            result.extend(flatten(item))
        else:
            result.append(item)
    return result
```

**题 8：用 `__new__` 实现单例** —— 思路：类属性存唯一实例，`__new__` 已存在就返回它。

```python
class Singleton:
    _instance = None
    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
```

**题 9：用 `contextmanager` 写一个计时上下文管理器** —— 思路：`yield` 前记开始时间，`yield` 后打印耗时。

```python
import time
from contextlib import contextmanager

@contextmanager
def timed():
    start = time.time()
    yield
    print(f"耗时 {time.time() - start:.3f}s")
```

**题 10：二分查找** —— 思路：双指针夹逼，注意 `mid` 用 `(lo + hi) // 2` 防溢出。

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

### 2.2 读代码说结果（3 题）

**题 A：可变默认参数**

```python
def add(x, lst=[]):
    lst.append(x)
    return lst

print(add(1))
print(add(2))
print(add(3, [10]))
print(add(4))
```

**答案：`[1]`、`[1, 2]`、`[10, 3]`、`[1, 2, 4]`。**

推导：默认列表 `[]` 在定义时创建一次，被前两次调用共享；第三次传了 `[10]`，走的是那个临时列表；第四次又回到共享的默认列表（此时是 `[1, 2]`），追加 `4` 得 `[1, 2, 4]`。

**题 B：循环里的 lambda 闭包陷阱**

```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)
print([f() for f in funcs])
```

**答案：`[2, 2, 2]`。**

推导：三个 lambda 都闭包捕获了同一个变量 `i`，循环结束后 `i` 是 `2`，所以调用时都返回 `2`。修复：用默认参数 `lambda i=i: i` 把当前值固定住。

**题 C：浅拷贝 vs 深拷贝**

```python
import copy
a = [[1, 2], [3, 4]]
b = copy.copy(a)
c = copy.deepcopy(a)
b[0].append(9)
c[0].append(8)
print(a)
print(b)
print(c)
```

**答案：`a = [[1, 2, 9], [3, 4]]`、`b = [[1, 2, 9], [3, 4]]`、`c = [[1, 2, 8], [3, 4]]`。**

推导：浅拷贝 `b` 的内层列表和 `a` 共享，所以 `b[0]` 改了 `a` 也变；深拷贝 `c` 完全独立，`c[0]` 是 `[1, 2]` 追加 `8` 得 `[1, 2, 8]`，不影响 `a`。

## 第四部分 · 面试技巧

### 4.1 遇到不会的问题怎么救场

**核心原则：面试官考的不是"背过没有"，而是"你的推理方式像不像一个真写过 Python 的人"。**

1. **先复述 + 确认**："你是说可变对象作为默认参数时会被共享，对吗？"——确认题意能避免跑偏，也给自己 20 秒思考时间。
2. **说出手头的判断框架**："这题本质是对象共享问题，我先想它是可变还是不可变。"——把题归类，答案就出来一半。
3. **从最小例子往回推**：先写 `def f(x=[]):` 一个最小例子，边写边说"我先保证能跑，再看第二次调用会怎样"。
4. **主动暴露盲点而不是硬编**："`__slots__` 的具体内存布局我记不精确，但我知道它是用固定槽位替代 `__dict__` 来省内存、牺牲动态加属性。"——承认边界 + 说相邻知识，远胜编一个错答案。
5. **收尾给验证方式**："我可以在解释器里跑 `f(); f()` 两次看第二次是否带了第一次的数据来验证。"——展示你会自测，这是强信号。
6. **如果彻底不会**：诚实降级——"这个我实战里没直接用 `multiprocessing` 的 `Pool`，但我理解它的思路是进程池 + 任务队列，和线程池对应，绕开 GIL。"诚实 + 给生产方案，通常不扣分。

### 4.2 可以反问面试官的 5 个问题

1. "团队现在 Python 版本是多少？有没有在推进类型标注和 mypy？还是保持动态风格？"——体现你懂动态/静态的取舍。
2. "后端并发主要是 asyncio 还是多进程/多线程？有没有遇到过 GIL 相关的性能问题？"——体现你懂 GIL 和并发的边界。
3. "代码风格上，团队是倾向鸭子类型还是强制类型标注 + 静态检查？"——体现你处理过真实类型权衡。
4. "异常处理有没有统一约定？比如哪些异常在边界捕获、哪些往上抛？"——体现你关心错误处理规范。
5. "测试是 pytest 为主吗？CI 里有没有跑 mypy、代码覆盖率门槛？"——体现你有工程化意识。

### 4.3 面试官最想听到的 3 个"实战信号"

1. **提到过真实踩坑**：讲一个具体故事比背概念有力。例如："我们一个接口的默认参数用了 `[]`，结果第二次请求带着第一次的数据，线上用户 A 看到了用户 B 的购物车。后来定了规矩：默认参数一律 `None`。"——细节越具体越可信。
2. **知道动态语言和静态检查的边界**：能说清"鸭子类型让代码灵活，但类型错误推迟到运行时，所以我们在边界处做运行时校验 + 用 mypy 补静态检查"；也知道类型标注在运行时被忽略、不影响性能。
3. **知道什么时候不炫技**：这是"会用"和"会炫"的分水岭。可以说："推导式超过两层嵌套、或者为了省一行把可读性搭进去时，我会退回普通循环。代码是给人读的，`for` 循环比一个 15 行的嵌套推导式更有价值。"
