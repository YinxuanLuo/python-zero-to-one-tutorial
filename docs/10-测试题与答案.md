## 第一关 · 概念快问快答（20 题）

判断下面每句话是**对**还是**错**。不要猜，想清楚理由。

1. Python 里列表（list）是可变对象，元组（tuple）是不可变对象。
2. `is` 和 `==` 是等价的判断，可以互换使用。
3. 字典的键必须是可哈希（hashable）的对象，所以元组可以作键、列表不可以。
4. `copy.copy()`（浅拷贝）和 `copy.deepcopy()`（深拷贝）对嵌套对象的处理方式相同。
5. 切片 `a[1:3]` 会创建一个新列表，不会修改原列表。
6. `range(10)` 返回的是一个列表。
7. Python 查找变量名的顺序是 Local → Enclosing → Global → Built-in（LEGB）。
8. 闭包是指函数记住了它定义时所在作用域的变量，即使那个作用域已经结束。
9. 装饰器本质上是一个"接收函数、返回新函数"的高阶函数。
10. `*args` 把多余的位置参数收集成元组，`**kwargs` 把多余的关键字参数收集成字典。
11. 函数默认参数写成 `def f(x=[])` 是安全的，因为每次调用都会创建新的空列表。
12. `self` 是 Python 的关键字，所以类方法的第一个参数只能叫 `self`。
13. 鸭子类型的意思是：判断一个对象能不能用，看它"有没有我需要的方法"，而不是看它的类型。
14. Python 中所有内置异常都继承自 `Exception`。
15. 类的继承查找顺序（MRO）可以用 `类名.__mro__` 或 `类名.mro()` 查看。
16. `with` 语句只能用于打开文件，不能用于自定义的上下文管理器。
17. GIL（全局解释器锁）导致 Python 的多线程在 CPU 密集型任务上无法实现真正的并行。
18. `asyncio` 是通过创建多个线程来实现并发的。
19. 类型标注（type hint）会改变程序的运行时行为，让代码跑得更快。
20. 列表推导式里不能包含 `if` 条件，例如不能写 `[x for x in nums if x > 0]`。

## 第三关答案

### 第 1 题：可变默认参数

**问题**：`cart=[]` 里的 `[]` 在**函数定义时**只创建一次，之后所有调用共享同一个列表。所以第二次调用会带着第一次的数据：

```text
['apple']
['apple', 'banana']
```

**修改**：默认值用 `None`，函数体内再创建新列表：

```python
def add_item(item, cart=None):
    if cart is None:
        cart = []
    cart.append(item)
    return cart

print(add_item("apple"))    # ['apple']
print(add_item("banana"))   # ['banana']
```

**核心教训**：**默认参数永远别用可变对象**。要"每次调用都是新的"，就用 `None` 占位、进去再建。

---

### 第 2 题：用 `is` 比较字符串

**问题**：`is` 比较的是对象身份，不是值。`name is "admin"` 只有在 `name` 恰好和那个 `"admin"` 是同一个被驻留（intern）的字符串对象时才为 `True`，换一个来源（比如从文件、网络读进来）就是 `False`。这属于"能跑但对错看运气"。

**修改**：比较值用 `==`：

```python
def is_admin(name):
    return name == "admin"
```

**核心教训**：**比较值一律用 `==`，`is` 只用来和 `None` 比较**（`x is None`）或判断是不是同一个对象。

---

### 第 3 题：浅拷贝当成深拷贝用

**问题**：`copy.copy` 只复制最外层列表，内层的 `[1, 2]`、`[3, 4]` 仍然被原对象和副本共享。所以改 `copied[0]` 会连累 `original`：

```text
[[1, 2, 99], [3, 4]]
```

**修改**：要完全独立用深拷贝：

```python
import copy

original = [[1, 2], [3, 4]]
copied = copy.deepcopy(original)
copied[0].append(99)
print(original)   # [[1, 2], [3, 4]]
```

**核心教训**：**只有一层结构用浅拷贝就够；有嵌套又想完全独立，用 `deepcopy`**。搞不清就永远用 `deepcopy`，代价只是慢一点。

### 第 4 题：字符串和数字直接拼接

**问题**：`"我今年 " + age` 里 `age` 是 `int`，Python 不会隐式转字符串，直接抛：

```text
TypeError: can only concatenate str (not "int") to str
```

**修改**：显式转换，或直接用 f-string：

```python
age = 18
message = f"我今年 {age} 岁"
print(message)   # 我今年 18 岁
```

**核心教训**：**字符串拼接用 f-string**，既显式又好看。这是"显式优于隐式"的典型体现。

---

### 第 5 题：闭包里修改外层变量漏了 `nonlocal`

**问题**：`count += 1` 等价于 `count = count + 1`，赋值让 Python 认为 `count` 是 `inc` 的**局部变量**，但读的时候还没赋值，抛：

```text
UnboundLocalError: cannot access local variable 'count' where it is
not associated with a value
```

**修改**：声明 `nonlocal`，告诉 Python 改的是外层变量：

```python
def make_counter():
    count = 0
    def inc():
        nonlocal count
        count += 1
        return count
    return inc

c = make_counter()
print(c())   # 1
```

**核心教训**：**闭包里要"改"外层变量必须加 `nonlocal`**；只"读"不需要。

### 第 6 题：装饰器丢失函数元数据

**问题**：`@timer` 之后，`fetch_data` 其实指向的是 `wrapper`，所以它的 `__name__` 变成了 `"wrapper"`，`__doc__` 也丢了。调试、日志、文档工具都会因此出错。

**修改**：用 `functools.wraps` 把原函数的元数据拷到 `wrapper` 上：

```python
import time
from functools import wraps

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时 {time.time() - start:.4f}s")
        return result
    return wrapper

@timer
def fetch_data():
    """拉取数据"""
    time.sleep(0.1)
    return "data"

print(fetch_data.__name__)   # fetch_data
```

**核心教训**：**写装饰器必加 `functools.wraps`**，一行就能保住 `__name__` / `__doc__` 等元数据。

### 第 7 题：裸 `except` 吞掉所有异常

**问题**：`except:` 不带类型会捕获**一切**，包括 `KeyboardInterrupt`（用户 Ctrl+C）、`SystemExit`，甚至你自己的逻辑 bug。后果：程序该崩的时候不崩，问题被静默掩盖。

**修改**：捕获具体异常：

```python
def parse_int(s):
    try:
        return int(s)
    except ValueError:
        return 0

print(parse_int("abc"))   # 0
```

**核心教训**：**`except` 后面永远写具体异常类型**。实在要兜底也写 `except Exception`，但 `KeyboardInterrupt` 这类系统级异常要放行。

---

### 第 8 题：`except` 顺序颠倒

**问题**：`except Exception` 写在前面，而 `ValueError` 是 `Exception` 的子类，所以第二个 `except ValueError` **永远不执行**。Python 匹配的是第一个能接住的 `except`。运行后你会发现后面的分支是死代码。

**修改**：子类在前、父类在后：

```python
def read_value():
    try:
        return int("not a number")
    except ValueError:
        return "不是数字"
    except Exception:
        return "出错了"
```

**核心教训**：**`except` 从具体到宽泛**，越具体的异常越靠前。

---

### 第 9 题：遍历字典时修改字典

**问题**：`for key in d` 是在迭代字典的键，迭代过程中 `del d[key]` 改变了字典大小，直接抛：

```text
RuntimeError: dictionary changed size during iteration
```

**修改**：先收集要删的键，遍历完再删（或遍历 `list(d)` 的副本）：

```python
d = {"a": 1, "b": 2, "c": 3}
for key in list(d):
    if d[key] % 2 == 0:
        del d[key]
print(d)   # {'a': 1, 'c': 3}
```

**核心教训**：**迭代一个可变容器时不要增删它**。先复制一份 `list(d)` 再迭代，或者用推导式生成新字典。

---

### 第 10 题：用乘法创建的嵌套列表共享引用

**问题**：`[[0] * 3] * 3` 里，外层的 `* 3` 是把**同一个内层列表的引用**复制三次，三个子列表其实是同一个对象。改 `grid[0][0]` 三个子列表全变：

```text
[[1, 0, 0], [1, 0, 0], [1, 0, 0]]
```

**修改**：用推导式让每一行都是独立的新列表：

```python
grid = [[0] * 3 for _ in range(3)]
grid[0][0] = 1
print(grid)   # [[1, 0, 0], [0, 0, 0], [0, 0, 0]]
```

**核心教训**：**列表乘法对"不可变元素"安全（如 `[0] * 3`），对"可变元素"是陷阱**。二维列表初始化一律用推导式。

## 第四关答案

### 1. 可变对象和不可变对象有什么区别？为什么重要？

**一句话**：可变对象（list、dict、set）创建后内容能改；不可变对象（int、str、tuple）每次"改"都产生新对象。重要，因为它决定了赋值、传参、哈希、默认参数等一系列行为。

**要点**：

- 可变：`a = [1]; a.append(2)`，`a` 还是那个对象，只是内容变了。
- 不可变：`s = "a"; s += "b"`，`s` 指向了一个**新的**字符串对象。
- 影响一：不可变对象可哈希，能作字典键；可变对象不行。
- 影响二：可变对象作为默认参数、作为共享引用时会有"被意外修改"的风险（第 03 章的可变默认参数）。

### 2. `is` 和 `==` 有什么区别？

**一句话**：`is` 比较对象身份（是不是同一个对象），`==` 比较值（相不相等）。

**要点**：

- `a = [1,2]; b = [1,2]`：`a == b` 为 `True`，`a is b` 为 `False`。
- `is` 本质是比 `id(a) == id(b)`。
- 唯一推荐用 `is` 的地方：和 `None` 比较（`x is None`），因为 `None` 是单例。
- 面试常追问：为什么 `is` 比 `==` 快？因为它只比指针，不触发 `__eq__`。
- 反直觉的例子（也是为什么别乱用 `is`）：

```python
a = "hello"
b = "hello"
print(a is b)   # True——字符串被 CPython 驻留了，碰巧是同一个对象
```

  这种"碰巧对"最坑人：它让你的代码在一个环境里通过、换一个环境就崩。所以**比较值永远用 `==`**。

### 3. 浅拷贝和深拷贝有什么区别？

**一句话**：浅拷贝只复制最外层，嵌套对象仍共享；深拷贝递归复制所有层级。

**要点**：

- 实现：`copy.copy`（浅）、`copy.deepcopy`（深）。
- 浅拷贝举例：`b = a.copy()` 或 `b = a[:]`，改 `b` 里嵌套的可变对象会连累 `a`。
- 深拷贝会复制任意层级的 list/dict/自定义对象，代价是慢、且遇到不可复制对象（如锁）会报错。
- 记忆：浅拷贝 = 复制一层皮，深拷贝 = 复制到底。

### 4. 列表和元组有什么区别？什么时候用元组？

**一句话**：列表可变、元组不可变。元组用于"结构固定、不该被改"的数据。

**要点**：

- 元组可哈希，能作字典键、能放进 set；列表不行。
- 元组比列表稍省内存，创建更快（但差异很小，别当主要理由）。
- 用元组的场景：函数的多个返回值、坐标 `(x, y)`、固定记录。
- 一个经典反例：元组里的列表元素仍然可变（`t = (1, [2])` 里的 `[2]` 能改）。

### 5. 什么是切片？`a[::-1]` 是干什么的？

**一句话**：切片用 `a[start:stop:step]` 取子序列；`a[::-1]` 是反转。

**要点**：

- `a[1:3]` 左闭右开，取下标 1、2。
- `a[::2]` 每两步取一个；`a[::-1]` 步长 -1 即反转整个序列。
- 切片产生新对象，原序列不动；字符串、列表、元组都支持切片。
- 常见坑：`a[1:3]` 越界不报错（自动截断），但 `a[10]` 单个索引越界报 `IndexError`。

### 6. 什么是推导式？列表推导式和生成器表达式区别？

**一句话**：推导式是把"循环 + 过滤 + 变换"压进一行的语法糖；列表推导式返回 list，生成器表达式返回惰性迭代器。

**要点**：

- 列表推导式：`[x*2 for x in range(10) if x%2==0]`，立即求值、占内存。
- 生成器表达式：`(x*2 for x in range(10))`，惰性、逐个产出、只能迭代一次。
- 字典推导式 `{k:v ...}`、集合推导式 `{x ...}` 同理。
- 选择：数据小要多次用 → 列表；数据大或只遍历一次 → 生成器。

### 7. 什么是 LEGB 作用域规则？

**一句话**：查找变量按 Local（函数内）→ Enclosing（外层闭包）→ Global（模块）→ Built-in（内建）的顺序，先找到先用。

**要点**：

- `Local`：当前函数内部定义的变量。
- `Enclosing`：嵌套函数的外层作用域，闭包读的就是它。
- `Global`：模块顶层。
- `Built-in`：`len`、`print` 这些内建名字。
- 关联：读变量走 LEGB；**赋值**默认在当前作用域创建新变量，想改外层要 `global` / `nonlocal`。

### 8. 什么是闭包？它解决了什么问题？

**一句话**：闭包是"函数 + 它定义时捕获的环境变量"，让函数离开定义它的作用域后仍能访问那些变量。

**要点**：

- 典型例子：`make_counter` 返回 `inc`，`inc` 记住了 `count`。
- 作用：在不引入类的情况下保存状态、做延迟执行、给装饰器提供"配置"。
- 关键：捕获的是变量本身（引用），不是值的快照——所以改外层要 `nonlocal`。
- 和 JS 的闭包是同一套概念，你有 JS 基础应该秒懂。
- 漏 `nonlocal` 的真实报错：

```python
def counter():
    n = 0
    def inc():
        n += 1      # 赋值让 n 变成局部变量，但读的时候还没赋值
        return n
    return inc
# 调用 inc() 会抛：
# UnboundLocalError: cannot access local variable 'n' where it is
# not associated with a value
```

### 9. 装饰器是什么？它的原理是什么？

**一句话**：装饰器是接收一个函数、返回一个新函数的高阶函数；`@deco` 就是 `func = deco(func)` 的语法糖。

**要点**：

- 典型用途：计时、日志、鉴权、缓存、重试。
- 原理三步：`wrapper` 里做前置/后置逻辑 → 调原函数 → 返回结果。
- 必须加 `functools.wraps` 保住原函数元数据（`__name__`、`__doc__`）。
- 进阶：带参数的装饰器要多包一层（"装饰器工厂"）；类也可以做装饰器（实现 `__call__`）。
- 等价写法要能脱口而出：

```python
@deco
def f():
    pass

# 完全等价于
f = deco(f)
```

### 10. `*args` 和 `**kwargs` 分别是什么？

**一句话**：`*args` 把多余的位置参数收集成元组，`**kwargs` 把多余的关键字参数收集成字典。

**要点**：

- `def f(*args, **kwargs)` 能接受**任意**调用方式。
- 反过来也能解包：`f(*[1,2])` 等价 `f(1,2)`，`f(**{"a":1})` 等价 `f(a=1)`。
- 名字 `args`/`kwargs` 是约定，真正起作用的是 `*` 和 `**`。
- 典型用途：装饰器的 `wrapper(*args, **kwargs)` 透传参数，转发给被包装函数。

### 11. 为什么默认参数不要用可变对象？正确写法？

**一句话**：默认参数在函数**定义时**只求值一次，可变对象会被所有调用共享、越攒越多；正确写法是默认 `None`，进函数再创建。

**要点**：

```python
def f(items=None):
    if items is None:
        items = []
    items.append(1)
    return items
```

- 这个坑的本质是 Python 的求值时机：默认值在 `def` 执行时就固定了。
- 对 int/str/None 这类不可变对象无影响，因为改了也是新对象。
- 面试官常让你现场演示两次调用 `f()` 的结果，答不出来说明没真写过 Python。

### 12. 什么是鸭子类型？它和"显式优于隐式"冲突吗？

**一句话**：鸭子类型是"看它会不会 `quack()`，不看它是不是 `Duck`"；它和"显式优于隐式"不冲突——显式约束行为，鸭子类型放宽类型。

**要点**：

- 例子：`def read_all(f): return f.read()` 不检查 `f` 的类型，只要它有 `.read()` 就行。
- 好处：不用写接口、不用继承，代码更灵活、更少样板。
- 代价：类型错误推迟到运行时才暴露，所以配合类型标注 + `mypy` 补上静态检查。
- 和 JS 的鸭子类型同源，但 Python 更进一步把它当成默认哲学。

### 13. `self` 是什么？`__init__` 和 `__new__` 有什么区别？

**一句话**：`self` 是实例方法第一个参数，指向调用它的那个实例；`__init__` 负责初始化实例，`__new__` 负责创建实例。

**要点**：

- `self` 不是关键字，是约定名，但必须是第一个参数，指向实例本身。
- `__new__` 先于 `__init__` 执行，返回实例（通常 `super().__new__(cls)`）。
- 99% 的场景你只写 `__init__`；`__new__` 用在单例、不可变类型的定制、元编程。
- 类方法用 `cls`（第一个参数是类），静态方法没有 `self`/`cls`。

### 14. 什么是 MRO？`super()` 是怎么工作的？

**一句话**：MRO 是多重继承时方法查找的顺序，Python 用 C3 线性化算法算出；`super()` 沿 MRO 找下一个实现。

**要点**：

- 查看：`类名.__mro__` 或 `类名.mro()`。
- `super()` 不是"找父类"，而是"按 MRO 找当前类后面的下一个"，所以多重继承里也能正确调用。
- 钻石继承（`D(B,C)`，`B/C(A)`）靠 C3 消除歧义，得到一个确定的顺序。
- 无法线性化（冲突的继承）会直接抛 `TypeError`，这是 C3 的保护。
- 一个钻石继承的 MRO 长这样：

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print(D.__mro__)
# (<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)
```

  注意顺序是 `D → B → C → A → object`，不是 `D → B → A → C`。`super()` 就是沿这条链往下走。

### 15. GIL 是什么？对多线程有什么影响？怎么绕开？

**一句话**：GIL 是 CPython 的全局解释器锁，同一时刻只允许一个线程执行 Python 字节码；它让多线程在 CPU 密集任务上无法真并行，但 I/O 密集不受影响。

**要点**：

- GIL 让多线程写起来更安全（简化了内存管理），代价是牺牲了 CPU 并行。
- I/O 密集（等网络、等磁盘）时线程会释放 GIL，多线程依然有效。
- 绕开方式：CPU 密集用 `multiprocessing`（多进程）；I/O 密集用 `asyncio`（协程）。
- 提醒：GIL 是 CPython 的实现细节，别的实现（如 Jython）没有 GIL。
- 选择口诀和对应工具：

| 场景 | 工具 | 为什么 |
|---|---|---|
| CPU 密集（算得多） | `multiprocessing` | 多进程各自有独立 GIL，真并行 |
| I/O 密集（等得多） | `threading` / `asyncio` | 等待时释放 GIL，并发有效 |
| 海量并发连接 | `asyncio` | 单线程事件循环，开销最小 |

### 第 1 题 · LRU 缓存

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.data = OrderedDict()

    def get(self, key):
        if key not in self.data:
            return -1
        self.data.move_to_end(key)      # 最近使用，移到末尾
        return self.data[key]

    def put(self, key, value):
        if key in self.data:
            self.data.move_to_end(key)
        self.data[key] = value
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)   # 弹出最久未用（最前面）
```

**验收要点**：`OrderedDict.move_to_end` 把访问项挪到最后，`popitem(last=False)` 弹出最老项——这就是 LRU 的全部秘密。容量 2、写 3 项后，最早那项 `get` 返回 `-1`。

### 第 2 题 · 记忆化装饰器

```python
from functools import wraps

def memoize(func):
    cache = {}
    @wraps(func)
    def wrapper(*args):
        if args not in cache:
            cache[args] = func(*args)
        return cache[args]
    return wrapper
```

**验收要点**：`args` 是不可变元组，能当字典键；`@wraps` 保证 `fib.__name__` 不变。加 `@memoize` 的递归 `fib(30)` 从指数级降到线性，瞬间出结果。

### 第 3 题 · 数据校验（鸭子类型版）

```python
def validate_user(data):
    errors = []

    name = data.get("name")
    age = data.get("age")

    if not isinstance(name, str) or name == "":
        errors.append("name 必须是非空字符串")
    if not isinstance(age, int) or isinstance(age, bool) or not (0 <= age <= 120):
        errors.append("age 必须是 0~120 之间的整数")

    return (len(errors) == 0, errors)
```

**验收要点**：函数只用 `data.get(key)`，不检查类型，所以任何"有 `.get()` 方法"的对象（dict、自定义类）都能通过——这就是鸭子类型。`isinstance(age, bool)` 那一段是防止 `True` 被当成 `1` 混进来（因为 `bool` 是 `int` 的子类）。

### 第 4 题 · 递归深拷贝

```python
def deep_copy(obj):
    if isinstance(obj, list):
        return [deep_copy(x) for x in obj]
    if isinstance(obj, dict):
        return {deep_copy(k): deep_copy(v) for k, v in obj.items()}
    if isinstance(obj, tuple):
        return tuple(deep_copy(x) for x in obj)
    if isinstance(obj, set):
        return {deep_copy(x) for x in obj}
    return obj
```

**验收要点**：分类型递归——`list`/`dict`/`tuple`/`set` 递归复制，其余（int/str 等不可变对象）直接返回。关键验证：改副本最里层，原对象不受影响。顺序上先判 `list`/`dict` 再判别的，因为 `isinstance` 是按类型精确匹配的。

### 第 5 题 · asyncio 并发任务

```python
async def run_all(tasks):
    results = []
    for coro in asyncio.as_completed(tasks):
        results.append(await coro)
    return results
```

**验收要点**：用 `asyncio.as_completed` 并发跑多个 `async` 任务，且**按完成先后**返回结果。总耗时约等于最慢的那个而不是所有之和——3 个分别 sleep 0.3/0.1/0.2 秒的任务，总耗时应在 0.3 秒左右。注意不能用 `asyncio.gather`：它返回顺序是传入顺序，不是完成顺序。
