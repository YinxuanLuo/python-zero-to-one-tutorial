# 第 04 章 · 面向对象

> 上一章你学会了函数、闭包、装饰器。这一章把"数据 + 操作数据的方法"打包成**类**。
> 你会从一个巨大的心智转变开始：**JS 用原型（prototype），Python 用类（class）**，然后一路讲到继承、魔术方法、鸭子类型。
>
> 本章你需要记住的就一件事：**Python 的"面向对象"是"数据和行为绑在一起"，但它骨子里仍是"鸭子类型"——判断一个东西靠不靠谱，看它有什么方法，不看它继承自谁。**

---

## 4.1 先做心智切换：JS 的原型 vs Python 的类

你写过 JS 的 `class`，但 JS 的 `class` 只是**原型继承的语法糖**——它底层还是 `prototype` 链。
Python 不一样，Python 是**货真价实的类继承**，从 1991 年第一天起就是。

这个区别对你意味着两件事，先说结论：

1. **Python 的 `class` 没有"语法糖"那一层**——它写出来是什么，运行时就是什么，没有 `prototype` 这种底层细节。
2. **Python 的继承关系更"死板"但更可预测**：多继承时有一套明确的顺序规则（MRO，4.5 节讲），不像 JS 的原型链那样绕。

先看两段等价的代码，感受差别。

JS：

```js
class Dog {
  constructor(name) {
    this.name = name;      // this 自动有，不用写
  }
  bark() {
    return `${this.name} 说：汪`;
  }
}
const d = new Dog("旺财");
```

Python：

```python
class Dog:
    def __init__(self, name):    # 构造函数叫 __init__，不叫 constructor
        self.name = name         # self 必须显式写，还得是第一个参数

    def bark(self):
        return f"{self.name} 说：汪"

d = Dog("旺财")
print(d.bark())
```

```text
旺财 说：汪
```

三个立刻能感受到的差别：

| 维度 | JavaScript | Python |
|---|---|---|
| 构造函数 | `constructor` | `__init__` |
| 访问自身 | `this`（隐式可用） | `self`（**必须显式写成第一个参数**） |
| 创建实例 | `new Dog()` | `Dog()`（**没有 `new`**） |
| 方法里引用自身 | `this.name` | `self.name` |

**注意没有 `new`**。Python 里 `Dog()` 就是创建实例，加个 `new` 反而是语法错误。

还有一个更大的差别：**Python 里"类"本身也是对象**（回忆第 00 章"万物皆对象"）。
`Dog` 这个类是一个 `type` 类型的对象，`d = Dog()` 是"调用"这个类对象，触发 `__init__` 造出实例。
这条认知对理解 `@classmethod`、元类（进阶）很有用，先有个印象。

> 一句话记住它：**JS 的 `class` 是原型的糖，Python 的 `class` 是原生类继承；`this` 变 `self`（要显式写），`new` 直接消失。**

## 4.2 `class`、`__init__`、`self`

这一节把三个最基础的东西讲透，尤其 `self`——它是最多新手栽跟头的地方。

### `__init__`：初始化，不是"构造"

Python 没有真正意义上的"构造函数"。`__init__` 干的是**初始化**：在对象已经创建好之后，往它身上塞属性。

```python
class Point:
    def __init__(self, x, y):
        self.x = x      # 给"这个实例"挂上属性 x
        self.y = y

p = Point(3, 4)
print(p.x, p.y)         # 3 4
```

```text
3 4
```

`self.x = x` 的意思是：给"当前这个实例"设置一个叫 `x` 的属性。左边的 `self.x` 是实例属性，
右边的 `x` 是参数。名字相同纯属巧合（也最常这么写），但它们是两个东西。

### `self` 到底是什么？

`self` 就是"这个实例自己"。它和 JS 的 `this` 是同一个概念，但有两点不同：

1. **Python 里 `self` 必须显式写在方法的第一个参数位置**，JS 的 `this` 是隐式存在的。
2. `self` **不是关键字**，只是一个约定俗成的参数名。你写成 `this` 也能跑，但没人这么干，写 `self` 是铁律。

为什么 Python 要"显式写 self"？这其实源自第 00 章那条哲学——**显式优于隐式**。
JS 的 `this` 有个臭名昭著的问题：它的值取决于"怎么调用"（谁调谁就是 `this`），于是满世界都是
`this` 绑定丢失的坑，逼得大家发明 `bind`、箭头函数来救。Python 干脆把"当前实例"作为**参数**传进去，
你一眼就能看到，不存在隐式绑定。

### 忘了写 `self`，会怎样？

这是新手最高频的报错。看：

```python
class Dog:
    def bark():          # 忘了写 self
        return "汪"

print(Dog().bark())
```

```text
TypeError: Dog.bark() takes 0 positional arguments but 1 was given
```

报错说 `bark()` 不收任何参数，却被传了 1 个。这个"被传的 1 个"就是实例本身——
Python 调用 `实例.方法()` 时，会**自动把实例作为第一个参数**传进去。你的方法没写 `self` 来接收它，
就多出来了。

翻译成人话：**`d.bark()` 等价于 `Dog.bark(d)`，你的 `bark` 必须有个 `self` 来接住这个 `d`。**

理解了这条，你就明白为什么所有方法第一个参数都是 `self` 了。

### 属性能随时加（和 JS 一样灵活）

Python 的实例属性是**动态**的，不像 Java 要先声明字段。你可以随时给实例挂新属性：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)
p.z = 5            # 事后加个 z，完全合法
print(p.x, p.y, p.z)
```

```text
3 4 5
```

代价是：拼错属性名不会报错（比如 `p.yy = 4` 只是新建了个 `yy`，不会提醒你），
这类拼写错误要等到运行时才爆。这正是后面 `__slots__`（4.12 节）和类型检查（第 07 章）想解决的部分问题。

> 一句话记住它：**`__init__` 是初始化不是构造；`self` 就是实例自己、必须显式写在第一个参数；`d.bark()` 会自动把 `d` 传进去。**

## 4.3 实例属性 vs 类属性，和那个"共享"的坑

Python 的属性分两种：**实例属性**（各实例各有一份）和**类属性**（整个类共享一份）。
这是 JS 里 `static` 与非 `static` 的对应物，但有个更容易踩的坑。

先看正常用法：

```python
class Cat:
    species = "猫科"      # 类属性：所有实例共享

    def __init__(self, name):
        self.name = name  # 实例属性：各自独立

c1 = Cat("咪咪")
c2 = Cat("球球")

print(c1.species, c2.species)   # 都读到了类属性
print(c1.name, c2.name)         # 实例属性互不影响
```

```text
猫科 猫科
咪咪 球球
```

`species` 定义在 `__init__` 外面、类体里，是类属性。所有实例都能通过 `c1.species` 读到它。
`name` 在 `__init__` 里通过 `self.name` 定义，是实例属性，各是各的。

### 坑：类属性是"可变对象"时，会跨实例共享

如果类属性是列表、字典这种可变对象，就踩坑了：

```python
class Team:
    members = []        # 类属性，且是可变的列表

    def add(self, name):
        self.members.append(name)

t1 = Team()
t2 = Team()

t1.add("alice")
t2.add("bob")

print(t1.members)   # 你以为只有 alice？
print(t2.members)
```

**真实输出是：**

```text
['alice', 'bob']
['alice', 'bob']
```

`t1` 加了 `alice`，结果 `t2` 的 `members` 里也有 `alice`！因为 `members` 是**类属性**，
`t1` 和 `t2` 都指向**同一个列表对象**，谁往里 `append` 都是改同一个列表。

**这跟 3.3 节"可变默认参数"是同一个坑的本质**：可变对象被共享，一处改，处处改。

### 正确做法：可变的东西放实例属性，在 `__init__` 里建

```python
class Team:
    def __init__(self):
        self.members = []   # 每个实例各建一个空列表

    def add(self, name):
        self.members.append(name)

t1 = Team()
t2 = Team()

t1.add("alice")
t2.add("bob")

print(t1.members)   # ['alice']
print(t2.members)   # ['bob']
```

```text
['alice']
['bob']
```

每个 `Team()` 创建时，`__init__` 都新建一个自己的 `members`，互不干扰。

### 还有第二个坑：实例赋值会"遮蔽"类属性

看这个更隐蔽的现象：

```python
class Cat:
    species = "猫科"

c = Cat()
print(c.species)        # 猫科（读到的是类属性）

c.species = "犬科"      # 你以为改了类属性？
print(c.species)        # 犬科（其实只是给 c 建了个实例属性）
print(Cat.species)      # 猫科（类属性根本没变！）
```

```text
猫科
犬科
猫科
```

`c.species = "犬科"` **不是修改类属性**，而是给实例 `c` 新建了一个同名的实例属性，把类属性"遮住"了。
类属性 `Cat.species` 依然是 `"猫科"`。

这条规则一句话总结：**读属性会沿"实例 → 类"往上找；但赋值永远只在实例上创建新属性，不会碰类属性。**
要真正改类属性，必须显式写 `Cat.species = "犬科"`。

> 一句话记住它：**类属性全类共享、实例属性各自独立；可变类属性会被所有实例共享着改，赋值实例属性只会"遮蔽"不会"改"类属性。**

## 4.4 继承与 `super()`

继承你熟，但 Python 有两个和 JS 不一样的细节：`super()` 的用法，以及多继承的 MRO（下一节）。

先看单继承：

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "……"

class Bird(Animal):                 # 括号里写父类
    def __init__(self, name, can_fly):
        super().__init__(name)      # 调用父类的 __init__
        self.can_fly = can_fly

    def speak(self):                # 重写父类方法
        return "啾啾"

b = Bird("小黄", can_fly=True)
print(b.name, b.speak(), b.can_fly)
```

```text
小黄 啾啾 True
```

几个要点：

1. **继承写法**：`class 子类(父类)`，父类写括号里。跟 JS 的 `class Bird extends Animal` 对应。
2. **`super().__init__(name)`**：调用父类的 `__init__`，把 `name` 交给父类去初始化。
   Python 3 里 `super()` 不需要写参数（老 Python 2 要写 `super(Bird, self)`，现在不用了）。
3. **方法重写**：子类定义了同名 `speak`，就覆盖父类的。调用 `b.speak()` 走的是子类的 `"啾啾"`。

### 不写 `super().__init__` 会怎样？

如果子类定义了 `__init__` 却忘了调 `super().__init__()`，父类的初始化就**不会执行**：

```python
class Animal:
    def __init__(self, name):
        self.name = name

class Bird(Animal):
    def __init__(self, name, can_fly):
        self.can_fly = can_fly    # 忘了调 super().__init__

b = Bird("小黄", True)
print(b.can_fly)   # True
print(b.name)      # 报错！
```

```text
True
AttributeError: 'Bird' object has no attribute 'name'
```

因为父类的 `__init__` 没跑，`self.name` 根本没被设置过。**子类一旦写了自己的 `__init__`，就完全接管了初始化，父类的 `__init__` 不会自动调。** 要复用父类逻辑，必须显式 `super().__init__()`。

### `isinstance` 和 `issubclass`：判断类型关系

```python
class Animal:
    pass

class Bird(Animal):
    pass

b = Bird()
print(isinstance(b, Bird))     # True，b 是 Bird 的实例
print(isinstance(b, Animal))   # True，子类实例也是父类实例
print(issubclass(Bird, Animal)) # True，Bird 是 Animal 的子类
print(issubclass(Animal, Bird)) # False，反过来不是
```

```text
True
True
True
False
```

这两个函数是"判断类型关系"的标准工具。鸭子类型（4.10 节）会告诉你：**大多数时候你根本不该用它们去分支**，但知道它们存在、能看懂别人的代码，是基本素养。

> 一句话记住它：**继承写 `class 子类(父类)`，子类重写 `__init__` 后必须显式 `super().__init__()` 否则父类初始化不会跑；`isinstance`/`issubclass` 判断类型关系。**

## 4.5 MRO 与多继承的菱形问题

这是 Python 面向对象里最有技术含量的一节，也是面试高频题。

先给结论：**当一个类继承多个父类，方法重名时，Python 用一套叫 MRO（Method Resolution Order，方法解析顺序）的规则，决定"到底调用哪个父类的方法"。** 你可以用 `类.mro()` 直接打印出这条顺序。

### 菱形问题：两个父类继承自同一个祖先

经典场景长这样：

```text
    A
   / \
  B   C
   \ /
    D
```

`B` 和 `C` 都继承 `A`，`D` 又同时继承 `B` 和 `C`。画出来像个菱形，所以叫"菱形问题"。
麻烦在于：如果 `B` 和 `C` 都定义了同名方法 `who`，`D` 该用哪个？

```python
class A:
    def who(self):
        return "A"

class B(A):
    def who(self):
        return "B>" + super().who()

class C(A):
    def who(self):
        return "C>" + super().who()

class D(B, C):
    def who(self):
        return "D>" + super().who()

print([c.__name__ for c in D.mro()])
print(D().who())
```

```text
['D', 'B', 'C', 'A', 'object']
D>B>C>A
```

`D.mro()` 打印出 `[D, B, C, A, object]`，这就是 Python 找方法的顺序：先 `D` 自己，然后 `B`，然后 `C`，然后 `A`，最后 `object`（所有类的最终基类）。

所以 `D().who()` 的执行过程是：

1. `D.who` 先跑，返回 `"D>" + super().who()`；
2. `super()` 按 MRO 找到下一个是 `B`，跑 `B.who`，返回 `"B>" + super().who()`；
3. `super()` 继续按 MRO 找到 `C`（**不是 A！**），跑 `C.who`，返回 `"C>" + super().who()`；
4. 最后 `super()` 找到 `A`，返回 `"A"`。

串起来就是 `D>B>C>A`。

**这里最反直觉的一点：`B` 的 `super()` 居然跳到了 `C`，而不是 `B` 的父类 `A`。**
因为 `super()` 不是"找我的父类"，而是"**顺着当前实例的 MRO 链，找下一个**"。当前实例是 `D`，
它的 MRO 是 `[D, B, C, A]`，所以 `B` 的 `super()` 往下走就是 `C`。

### MRO 的规则：C3 线性化

这条顺序不是拍脑袋定的，而是由 **C3 线性化算法**算出来的（名字记不住没事，记住规则）：

1. 子类永远排在父类前面；
2. 多个父类的顺序，按 `class D(B, C)` 里写的顺序来（`B` 在 `C` 前）；
3. 每个类在链上只出现一次。

`D(B, C)` 里 `B` 写在 `C` 前面，所以 MRO 里 `B` 排在 `C` 前面。

### 不是所有多继承都合法

C3 算法能算出 MRO，前提是父类顺序"不矛盾"。如果写矛盾了，Python **直接不让你定义这个类**：

```python
class A:
    pass

class B(A):
    pass

class C(A):
    pass

class D(B, C):
    pass
```

上面这个能通过。但如果你写成：

```python
class A:
    pass

class B(A):
    pass

class C(B):      # 注意：C 继承 B
    pass

class D(B, C):   # 这种矛盾顺序会报错
    pass
```

运行会看到：

```text
TypeError: Cannot create a consistent method resolution order (MRO) for bases B, C
```

Python 宁可拒绝创建这个类，也不给你一个"顺序存疑"的继承结构。这又是"猜错不如报错"。

### 多继承值得用吗？

诚实说：**日常业务里，多继承用得很少，菱形继承更少。** Python 之所以允许，主要是给"混入（Mixin）"这种模式留门——
一个类不负责完整功能，只"混入"一小块能力（比如"可序列化""可比较"），多个 Mixin 可以组合。

但正因为少见、又有 MRO 这个隐藏规则，面试官特别爱拿菱形问题考你"是不是真懂"。你把 `super()` 是"按 MRO 找下一个"这条记住，就赢过一半人。

> 一句话记住它：**多继承靠 MRO（C3 线性化）定顺序，`类.mro()` 能打印；`super()` 不是"找父类"而是"沿当前实例的 MRO 找下一个"，所以菱形里会走出 `D→B→C→A`。**

## 4.6 `@property` 与 `@setter`

还记得第 03 章学的装饰器吗？这里立刻派上用场。`@property` 就是个装饰器，它把**方法伪装成属性**。

先看问题：为什么需要它？

假设你有个类，里面有个"面积"是算出来的，不是存出来的：

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14159 * self.radius ** 2

c = Circle(2)
print(c.area())    # 用起来像方法，得加括号
```

```text
12.56636
```

`area` 本质是个计算，但"面积"在概念上是个**属性**，不是"动作"。让调用方写 `c.area()` 有点别扭——
更自然的应该是 `c.area`。`@property` 就是干这个的：

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def area(self):
        return 3.14159 * self.radius ** 2

c = Circle(2)
print(c.area)    # 不用括号了，看起来就是属性
```

```text
12.56636
```

`@property` 让 `area` 变成"只读属性"——调用方写 `c.area`（没有括号），Python 内部会自动调用那个方法。

### 为什么要"伪装"？为了封装和数据校验

`@property` 最值钱的应用是**带校验的赋值**。看这个温度类：

```python
class Temperature:
    def __init__(self):
        self._celsius = 0      # 内部真正存数据的属性，惯例加下划线前缀

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("低于绝对零度")
        self._celsius = value

t = Temperature()
t.celsius = 25        # 走 setter，做校验
print(t.celsius)      # 25

t.celsius = -500      # 触发校验
```

```text
25
ValueError: 低于绝对零度
```

外面的人写 `t.celsius = 25`，看起来就是"赋值给一个属性"，但实际走的是 `setter` 方法，
里面做了"不能低于绝对零度"的校验。外面的人写 `t.celsius`，走的是 `getter`，返回内部的 `_celsius`。

**这就是封装**：调用方不用知道"温度存的是摄氏度还是开尔文、存的是属性还是算的"，它只管用 `t.celsius` 这个"接口"。
哪天你想把内部改成存开尔文，外面代码一行不用动。

### 关键细节：内部属性加下划线

注意 `self._celsius` 前面有个下划线。这是 Python 的**约定**（不是语法强制）：`_x` 表示"这是内部用的，别在外面碰"。
如果用 `self.celsius` 存，会和 `@property` 的 `celsius` 名字冲突，直接无限递归。所以惯例是：
**`@property` 名字叫 `celsius`，内部存储属性叫 `_celsius`。**

### 只读属性：不写 setter

如果只写 `@property` 不写 `@xxx.setter`，那这个属性就是**只读**的：

```python
class Point:
    def __init__(self, x):
        self._x = x

    @property
    def x(self):
        return self._x

p = Point(3)
print(p.x)     # 3
p.x = 10       # 试图赋值
```

```text
3
AttributeError: property 'x' of 'Point' object has no setter
```

报错很直白：这个 property 没有 setter，不能赋值。这就实现了"只读属性"。

> 一句话记住它：**`@property` 把方法伪装成属性（读），`@xxx.setter` 伪装赋值（写）并在里面做校验；内部存储属性惯例加 `_` 前缀。**

---

## 4.7 `@classmethod` 与 `@staticmethod`

这两个装饰器解决同一个问题：**有些方法不属于"某一个实例"，而是属于"类本身"。**
区别在于，它们拿到的第一个参数不一样。

### `@classmethod`：第一个参数是"类"

```python
class Config:
    default_port = 8080

    @classmethod
    def get_port(cls):          # 第一个参数是类本身，惯例叫 cls
        return cls.default_port

print(Config.get_port())        # 直接类名调用
print(Config().get_port())      # 用实例调用也行
```

```text
8080
8080
```

`@classmethod` 的方法，第一个参数是**类本身**（惯例命名 `cls`，对应 `self` 是"实例"）。
它最典型的作用是**替代构造函数**——比如"从不同格式的数据构造一个对象"：

```python
class Date:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day

    @classmethod
    def from_string(cls, text):           # 从 "2026-10-12" 构造
        year, month, day = text.split("-")
        return cls(int(year), int(month), int(day))

d = Date.from_string("2026-10-12")
print(d.year, d.month, d.day)
```

```text
2026 10 12
```

`Date.from_string(...)` 是一个"备用构造入口"，返回一个 `Date` 实例。用 `cls` 而不是写死 `Date`，
是为了子类继承时 `cls` 能自动指向子类（这是 `classmethod` 相对 `staticmethod` 的核心优势）。

### `@staticmethod`：既不拿实例，也不拿类

```python
class Validator:
    @staticmethod
    def is_valid_port(value):     # 没有 self，也没有 cls
        return 0 <= value <= 65535

print(Validator.is_valid_port(8080))   # True
print(Validator.is_valid_port(99999))  # False
```

```text
True
False
```

`@staticmethod` 就是一个"放在类里的普通函数"，它不用 `self` 也不用 `cls`。
把它放类里，只是为了**逻辑上归类**（"这个函数和这个类相关"），方便组织代码。

### 什么时候用哪个？

| 场景 | 用什么 |
|---|---|
| 需要访问"实例"的数据 | 普通方法（`self`） |
| 需要访问"类"本身（读类属性、替代构造） | `@classmethod`（`cls`） |
| 和类相关，但不需要访问实例/类 | `@staticmethod` |

一句话判断：**要动实例 → 普通方法；要动类 → classmethod；都不动但想归类 → staticmethod。**

> 一句话记住它：**`@classmethod` 拿类 `cls`（用于替代构造、读类属性），`@staticmethod` 什么都不拿（纯归类）；普通方法拿实例 `self`。**

---

## 4.8 魔术方法（一）：`__str__` / `__repr__` / `__eq__` / `__lt__`

魔术方法（dunder methods，double underscore 的缩写）是 Python 面向对象最迷人的地方。
它们都是 `__xxx__` 形式，**你不用显式调用它们，Python 会在特定语法/操作时自动调用**。

先记住一个总原则：**你定义这些方法，等于告诉 Python"我的对象遇到 `print`、`==`、`<`、`len()`、`obj[i]` 时该怎么表现"。**

### `__str__` 和 `__repr__`：让对象能"打印"

先看没有定义这两个方法时，打印一个对象多难看：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)
print(p)      # <__main__.Point object at 0x000001F3A2B1C0D0>
```

```text
<__main__.Point object at 0x000001F3A2B1C0D0>
```

那一串 `<__main__.Point object at 0x...>` 就是默认的 `__repr__`，除了内存地址啥也没有。
定义它俩之后：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __str__(self):                       # 给用户看：print、str()
        return f"({self.x}, {self.y})"

    def __repr__(self):                      # 给开发者看：repr()、容器里
        return f"Point({self.x}, {self.y})"

p = Point(3, 4)
print(p)                    # 走 __str__ → (3, 4)
print(repr(p))              # 走 __repr__ → Point(3, 4)
print([p, Point(1, 1)])     # 容器里元素走 __repr__
```

```text
(3, 4)
Point(3, 4)
[Point(3, 4), Point(1, 1)]
```

区别一句话记住：

- **`__str__` 是给人看的**，`print` 和 `str()` 调用它，力求友好；
- **`__repr__` 是给开发者看的**，`repr()` 调用它，理想情况下"复制这段代码能重建对象"；
- **容器（列表、字典）里的元素，永远走 `__repr__`**，因为容器显示是给开发者调试用的。

一个实用建议：**如果只写一个，写 `__repr__`**（`__str__` 在没定义时会自动回退到 `__repr__`）。

### `__eq__`：让 `==` 有意义

默认情况下，`==` 比的是"是不是同一个对象"（相当于 `is`），不是"值相不相等"：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p1 = Point(3, 4)
p2 = Point(3, 4)
print(p1 == p2)   # False！值一样但对象不同
```

```text
False
```

两个坐标相同的点，`==` 却说它们不等。定义 `__eq__` 后：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)

p1 = Point(3, 4)
p2 = Point(3, 4)
print(p1 == p2)   # True
print(p1 != p2)   # False（!= 会自动取 == 的反）
```

```text
True
False
```

`__eq__` 定义了"相等"的规则。定义它之后，`==` 和 `!=` 都按你的规则走。

### `__lt__`：让 `<`、`sorted` 可用

`__lt__` 是 "less than"，定义"小于"的规则。定义它之后，对象就能比较大小、能排序：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __lt__(self, other):     # 按"到原点的距离"比较
        return self.x ** 2 + self.y ** 2 < other.x ** 2 + other.y ** 2

    def __repr__(self):
        return f"Point({self.x}, {self.y})"

points = [Point(3, 4), Point(1, 1), Point(0, 5)]
print(sorted(points))   # 按距离升序
```

```text
[Point(1, 1), Point(3, 4), Point(0, 5)]
```

`sorted` 内部就是靠 `__lt__` 来两两比较的。`Point(1,1)` 距离最近排最前，`Point(0,5)` 距离最远排最后。

> 一句话记住它：**魔术方法是"让对象融入 Python 语法"的钩子——`__str__` 管 `print`、`__repr__` 管调试、`__eq__` 管 `==`、`__lt__` 管 `<` 和排序。**

## 4.9 魔术方法（二）：`__len__` / `__getitem__` 让对象像容器

上一节让对象能"打印、比较"。这一节更猛：**让你的对象假装成一个容器（列表/字典），直接用 `len()`、`obj[i]`。**

### `__len__`：让 `len()` 可用

```python
class Playlist:
    def __init__(self):
        self.songs = []

    def add(self, song):
        self.songs.append(song)

    def __len__(self):
        return len(self.songs)

p = Playlist()
p.add("晴天")
p.add("稻香")
print(len(p))   # 2，直接用 len()
```

```text
2
```

`len(p)` 会自动调用 `p.__len__()`。现在你的 `Playlist` 用起来就像个列表一样有长度。

### `__getitem__`：让 `obj[i]` 可用

```python
class Playlist:
    def __init__(self):
        self.songs = ["晴天", "稻香", "七里香"]

    def __getitem__(self, index):
        return self.songs[index]

p = Playlist()
print(p[0])     # 晴天
print(p[1:])    # ['稻香', '七里香']  切片也支持！
```

```text
晴天
['稻香', '七里香']
```

`p[0]` 会自动调用 `p.__getitem__(0)`。而且只要定义了 `__getitem__`，**切片 `p[1:]`、`for` 循环遍历**都自动可用——
因为 Python 的 `for` 循环和切片都建立在"取值"这个动作上。

### 一起用：让对象彻底像容器

```python
class Team:
    def __init__(self, members):
        self.members = list(members)

    def __len__(self):
        return len(self.members)

    def __getitem__(self, index):
        return self.members[index]

    def __contains__(self, name):   # 让 in 可用
        return name in self.members

t = Team(["alice", "bob", "carol"])
print(len(t))            # 3
print(t[0])              # alice
print("bob" in t)        # True
print(list(t))           # ['alice', 'bob', 'carol']
```

```text
3
alice
True
['alice', 'bob', 'carol']
```

定义了 `__len__`、`__getitem__`、`__contains__` 后，`len`、下标、`in`、`list()` 全都通了。
你的类成了一个"自定义容器"，所有依赖容器协议的函数（`sorted`、`sum`、`for`）都能直接吃下它。

### 一个提醒：别滥用

魔术方法很爽，但**别为了炫技给类加一堆没必要的魔术方法**。规则是：**只有当你的类"语义上确实像"某个东西时，才去实现对应的魔术方法。**
比如 `Playlist` 语义上"就是一个歌单列表"，实现 `__len__`/`__getitem__` 合理；但一个"数据库连接对象"去实现 `__lt__` 就很怪。

> 一句话记住它：**`__len__` 让 `len()` 可用，`__getitem__` 让 `obj[i]`、切片、`for` 可用，配合起来你的类就能像容器一样被所有标准函数吃下。**

## 4.10 鸭子类型：不看类型看行为

终于到本章的压轴概念了。**鸭子类型（duck typing）** 的名字来自一句谚语：

> 如果一个东西走起来像鸭子、叫起来像鸭子，那它就是鸭子。

翻译成 Python：**判断一个对象靠不靠谱，不看它继承自哪个类，只看它有没有你需要的方法。**

看例子：

```python
class Duck:
    def quack(self):
        return "嘎"

class Person:
    def quack(self):
        return "我在模仿鸭子"

def make_quack(thing):
    return thing.quack()    # 不检查类型，直接调用

print(make_quack(Duck()))    # 嘎
print(make_quack(Person()))  # 我在模仿鸭子
```

```text
嘎
我在模仿鸭子
```

`make_quack` 的参数没有类型限制。它只关心一件事：**传入的对象有没有 `.quack()` 方法**。
有，就能跑；没有，运行时才报 `AttributeError`。`Duck` 和 `Person` 没有任何继承关系，
但它们"叫得出来"，所以都能用。

### 对比：静态类型语言会怎么写？

在 Java 这类静态类型语言里，你得先定义一个 `Quackable` 接口，让 `Duck` 和 `Person` 都去实现它，
然后 `make_quack` 声明参数类型是 `Quackable`。一套下来样板代码一大堆。

Python 直接跳过这一切：**只要你会 `quack`，我不管你是什么。** 这就是鸭子类型。

### 它和第 00 章的"显式优于隐式"冲突吗？

不冲突。回忆 00 章的话：

- **显式**针对的是"行为"——你要调用什么方法，必须写出来（`thing.quack()` 就是显式调用）；
- **鸭子类型**针对的是"类型"——不要求你声明 `thing` 是什么类型，只要行为对就行。

鸭子类型让代码**更灵活**：你可以传任何"能叫"的东西进来，包括你之后新写的、完全没预想到的类。
代价是**类型错误推迟到运行时**——传个 `int` 进来，要等到调用 `.quack()` 那一刻才报 `AttributeError`，
而不是编译期就拦住。

### 鸭子类型在标准库里的体现

Python 自己就大量用鸭子类型。比如 `sorted` 不要求你传"列表"，只要求你传"可迭代的东西"——
列表、元组、字符串、生成器、你自定义的类，只要能一个个取出元素，`sorted` 都吃：

```python
print(sorted([3, 1, 2]))      # 列表
print(sorted((3, 1, 2)))      # 元组
print(sorted("cba"))          # 字符串
print(sorted({3, 1, 2}))      # 集合
```

```text
[1, 2, 3]
[1, 2, 3]
['a', 'b', 'c']
['b', 'a', 'c']
```

四种完全不同的类型，`sorted` 一视同仁，因为它的要求是"可迭代"而不是"是列表"。

再比如 `sum`、`max`、`for` 循环，全都是"鸭子类型"的拥趸。这也是为什么你在上一节定义 `__getitem__` 后，
`list(t)` 就自动好使——因为 `list()` 只要求对象"可迭代"，你的类做到了。

### 什么时候该用 `isinstance` 做类型判断？

鸭子类型的反面是"显式类型检查"。结论：**业务代码里尽量用鸭子类型，别用 `isinstance` 去分支。**

```python
# ❌ 反模式：硬检查类型
def speak(animal):
    if isinstance(animal, Duck):
        return animal.quack()
    elif isinstance(animal, Dog):
        return animal.bark()
    # 每加一种动物，都要改这里

# ✅ 鸭子类型：直接调，能叫就行
def speak(animal):
    return animal.speak()
```

`isinstance` 分支的问题是：**每新增一种类型，你都要回来改函数**，违背开闭原则。
鸭子类型直接调方法，新类型只要实现了 `speak()` 就能用，函数一行不用动。

> 一句话记住它：**鸭子类型不看类型看行为——只要对象有你要的方法就能用，类型错误推迟到运行时；能用鸭子类型就别用 `isinstance` 分支。**

## 4.11 鸭子类型和类型标注的关系

上一节讲了鸭子类型"灵活但没约束"。你可能会问：**那 Python 的类型标注（type hints）是不是在反对鸭子类型？**

先给结论：**不反对，是互补。** 类型标注是"写给人看、给工具看的提示"，它**不会在运行时强制检查**。
换句话说，你写了类型标注，Python 依然照跑不误，该鸭子类型还是鸭子类型。

看：

```python
def greet(name: str) -> str:      # 标注：参数是 str，返回 str
    return "hello, " + name

print(greet("alice"))    # 正常
print(greet(123))        # 传了 int，运行时也不报错！
```

```text
hello, alice
hello, 123
```

`name: str` 只是标注，`greet(123)` 照样执行（`"hello, " + 123` 会报 `TypeError`，因为 `str + int` 不合法，
但这不是"类型标注"拦下的，是 `+` 运算本身拦下的）。要真正让标注生效，得用 `mypy` 这类**静态检查工具**，
在运行**之前**扫描代码报错——这件事第 07 章专门讲。

所以两者的关系是：

| | 鸭子类型 | 类型标注 |
|---|---|---|
| 检查时机 | 运行时（调用那一刻） | 静态（写代码时，靠工具） |
| 是否强制 | 是（缺方法就报错） | 否（不检查也能跑） |
| 目的 | 灵活、少样板 | 提前发现类型错误、当文档 |

**它们是"运行时"和"静态"两个层面的配合**，不是二选一。实际工程里的主流做法是：
鸭子类型写逻辑（灵活），类型标注做文档 + 让 `mypy`/IDE 帮你查错（安全）。

> 一句话记住它：**类型标注是给人和工具看的提示，运行时不强制；鸭子类型是运行时的真实行为——二者一个管"写之前"，一个管"跑起来"。**

## 4.12 `__slots__`（可选，进阶）

这一节可看可不看，但面试偶尔问，知道它能加分。

先回顾 4.2 节的一个事实：**Python 的实例属性是动态的，每个实例背后都有一个 `__dict__` 字典来存属性。**
这个字典很方便（能随时加属性），但很费内存——每个实例都背着一个字典。

`__slots__` 就是告诉你：**这个类只能有这几个属性，别给我准备 `__dict__` 了，直接按固定槽位存。**
代价是省内存，但失去了"随时加属性"的自由。

```python
class Point:
    __slots__ = ("x", "y")     # 只允许 x、y 两个属性

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
print(p.x, p.y)               # 1 2
print(hasattr(p, "__dict__")) # False，没有实例字典了
```

```text
1 2
False
```

看到 `hasattr(p, "__dict__")` 是 `False`——实例不再背字典，内存省下来了。

### 代价：不能乱加属性

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
p.z = 3        # 试图加个 z
```

```text
AttributeError: 'Point' object has no attribute 'z' and no __dict__ for setting new attributes
```

报错说得很清楚：没有 `z` 这个属性，而且连 `__dict__` 都没有，没法现场新建。

### 什么时候用 `__slots__`？

**几乎只有一种场景值得用：你要创建海量的小对象，内存吃紧。** 比如一个游戏里几百万个坐标点，
每个都省掉一个字典，内存差一个数量级。日常业务里，**别用**——牺牲灵活性换来的那点内存不值得。

还有两个坑顺带记一下：

1. 用了 `__slots__` 的类，实例不能再用 `__dict__` 存额外属性（上面看到了）；
2. `__slots__` 不影响继承——子类如果没声明自己的 `__slots__`，还是会有 `__dict__`。

> 一句话记住它：**`__slots__` 用"固定槽位"替代实例字典来省内存，代价是禁止动态加属性；只在海量小对象内存吃紧时才值得用。**

## 4.13 本章常见坑速查

| 坑 | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 忘写 `self` | `TypeError: foo() takes 0 positional arguments but 1 was given` | `d.foo()` 自动把实例传进去，方法没接 | 所有实例方法第一个参数写 `self` |
| 加了 `new` | `SyntaxError` | Python 没有 `new` 关键字 | 直接用 `ClassName()` 创建 |
| 可变类属性共享 | 一个实例 `append`，别的实例也看到了 | 类属性是同一个可变对象 | 可变数据放 `__init__` 里建实例属性 |
| 实例赋值"改"类属性 | 改了 `obj.attr` 类属性没变 | 赋值只在实例上建新属性（遮蔽） | 改类属性写 `ClassName.attr = x` |
| 子类忘调 `super().__init__` | 访问父类初始化的属性报 `AttributeError` | 子类 `__init__` 完全接管，父类不自动跑 | 显式 `super().__init__(...)` |
| 菱形继承 `super` 走错 | 以为 `B.super()` 找 `A`，结果找了 `C` | `super()` 沿当前实例的 MRO 找下一个 | 记住 `super()` 是"按 MRO 找下一个" |
| property 与存储属性同名 | 无限递归 `RecursionError` | `self.x = ...` 又触发 setter | 存储属性用 `_x` 下划线前缀 |
| 只读 property 被赋值 | `AttributeError: ... has no setter` | 只写了 `@property` 没写 setter | 要么补 setter，要么接受只读 |
| `==` 比不出想要的 | 值相同却 `False` | 默认 `==` 比对象身份 | 定义 `__eq__` |
| 打印对象一坨地址 | `<... object at 0x...>` | 没定义 `__str__`/`__repr__` | 至少定义 `__repr__` |
| `len(obj)` 报错 | `TypeError: object of type ... has no len()` | 没定义 `__len__` | 定义 `__len__` |
| 用 `isinstance` 到处分支 | 每加新类型都要改函数 | 违背开闭原则 | 优先鸭子类型，直接调方法 |
| `__slots__` 后加属性 | `AttributeError: ... no __dict__` | 槽位定死，无实例字典 | 非内存敏感场景别用 `__slots__` |

## 4.14 本章小结

- **JS 是原型、Python 是原生类继承**：`this` 变 `self`（显式写），`new` 消失，构造函数叫 `__init__`。
- **`__init__` 是初始化不是构造**，`self` 是实例自己，`d.m()` 等价于 `Class.m(d)`。
- **实例属性各是各的，类属性全类共享**；可变类属性会被所有实例共享着改。
- **赋值实例属性只会"遮蔽"类属性**，要改类属性得写 `ClassName.attr = x`。
- **继承写 `class 子(父)`**，子类重写 `__init__` 必须显式 `super().__init__()`，否则父类初始化不跑。
- **多继承靠 MRO（C3 线性化）定顺序**，`类.mro()` 可打印；`super()` 是"沿 MRO 找下一个"不是"找父类"。
- **`@property` 把方法伪装成属性**，`@xxx.setter` 做赋值校验，存储属性加 `_` 前缀，缺 setter 即只读。
- **`@classmethod` 拿类 `cls`、`@staticmethod` 什么都不拿、普通方法拿实例 `self`**。
- **魔术方法是语法钩子**：`__str__`（print）、`__repr__`（调试/容器）、`__eq__`（`==`）、`__lt__`（`<`/排序）、`__len__`（`len`）、`__getitem__`（`obj[i]`/切片/遍历）。
- **鸭子类型不看类型看行为**：有方法就能用，类型错误推迟到运行时；优先鸭子类型而非 `isinstance` 分支。
- **类型标注是静态提示，运行时不强制**，和鸭子类型是互补而非对立。
- **`__slots__` 用固定槽位省内存**，代价是禁止动态加属性，只在海量小对象场景值得用。

## 4.15 动手练习

1. 写一个 `BankAccount` 类：`__init__` 接收初始余额，有 `deposit(amount)` 和 `withdraw(amount)` 方法，
   取款金额超过余额时抛 `ValueError("余额不足")`。

   <details><summary>参考答案</summary>

   ```python
   class BankAccount:
       def __init__(self, balance=0):
           self.balance = balance

       def deposit(self, amount):
           self.balance += amount

       def withdraw(self, amount):
           if amount > self.balance:
               raise ValueError("余额不足")
           self.balance -= amount

   acct = BankAccount(100)
   acct.deposit(50)
   acct.withdraw(30)
   print(acct.balance)   # 120
   ```

   </details>

2. 用 `@property` 给一个 `Rectangle` 类实现"只读"的 `area` 属性（面积 = 宽 × 高），
   再验证直接给 `area` 赋值会报 `AttributeError`。

   <details><summary>参考答案</summary>

   ```python
   class Rectangle:
       def __init__(self, width, height):
           self.width = width
           self.height = height

       @property
       def area(self):
           return self.width * self.height

   r = Rectangle(3, 4)
   print(r.area)   # 12
   # r.area = 100   # 取消注释会报 AttributeError: property 'area' of 'Rectangle' object has no setter
   ```

   </details>

3. 写一个 `Student` 类，实现 `__eq__`（按学号判断相等）和 `__lt__`（按成绩比较），
   让两个学号相同的学生 `==` 为真，并让 `sorted` 能按成绩排序。

   <details><summary>参考答案</summary>

   ```python
   class Student:
       def __init__(self, name, student_id, score):
           self.name = name
           self.student_id = student_id
           self.score = score

       def __eq__(self, other):
           return self.student_id == other.student_id

       def __lt__(self, other):
           return self.score < other.score

       def __repr__(self):
           return f"Student({self.name}, {self.score})"

   s1 = Student("alice", "001", 90)
   s2 = Student("bob", "001", 80)
   s3 = Student("carol", "002", 95)
   print(s1 == s2)                  # True，学号相同
   print(sorted([s1, s2, s3]))      # 按成绩排序
   ```

   </details>

4. 用鸭子类型写一个函数 `feed(animal)`，调用动物的 `eat()` 方法。然后定义两个没有继承关系的类
   `Dog` 和 `Robot`，各自实现 `eat()`，把两个实例都传给 `feed` 验证都能跑。

   <details><summary>参考答案</summary>

   ```python
   class Dog:
       def eat(self):
           return "狗在啃骨头"

   class Robot:
       def eat(self):
           return "机器人充电中"

   def feed(animal):
       return animal.eat()

   print(feed(Dog()))    # 狗在啃骨头
   print(feed(Robot()))  # 机器人充电中
   ```

   </details>

5. 写出下面菱形继承的 MRO 顺序，并说明 `D().who()` 的输出：

   ```python
   class A:
       def who(self):
           return "A"

   class B(A):
       def who(self):
           return "B>" + super().who()

   class C(A):
       def who(self):
           return "C>" + super().who()

   class D(B, C):
       def who(self):
           return "D>" + super().who()
   ```

   <details><summary>参考答案</summary>

   MRO 是 `[D, B, C, A, object]`。`D().who()` 输出 `D>B>C>A`。
   因为 `super()` 沿当前实例（`D`）的 MRO 找下一个：`D` → `B` → `C` → `A`，不是 `B` 的父类 `A`。

   </details>
